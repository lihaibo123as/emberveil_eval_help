## 判据正文（自宿主 `CLAUDE.md` 抽取）
- ★★★**「原始尺寸」是我们观测不到的东西**（1.75.49，子插件 `EH_DebugBox` 图层调试；用户报障「排查下原始尺寸/当前尺寸是否正确」）：**现在只剩三级**（★1.75.52 探索层适配摘除 ⇒ 原「地图适配」那一级 / `EVAL_SM_ORIG_OF` **已整条删除**）= **自定义前**（我们第一次写之前读到的 = **唯一能当还原依据的真值**，写入点 `uiCustEnsure`）> **首次观测**（本会话首见，**不是系统原值** —— DragFrames 还原过 / 客户端自己摆过，记下的就是改过的值）> **无记录**（旧写法在这里返回当前尺寸并标「当前」⇒ 界面永远「原 = 当前」，正是用户起疑的点；现在如实写「未知」）。
  两条配套铁律：① **复用纹理（`WorldMapOverlay*`）的观测基线必须按地图身份分桶**（`uiSz.origKey` = `路径@file:WxH`；地图身份读不到 ⇒ **不记**）—— 同一名字在不同图上是不同矩形（R20c/R20d）；② **读回口径绝不押注**：拿屏幕实测（`GetRight−GetLeft`）与「原样读回」「读回×有效缩放」当场比（`uiSz.class`），对上哪个标哪个、都对不上就如实写「判不出」（SimpleMap 那一案与本文件 `/edb maptile diag` 两次实测结论本就互相矛盾）。
  ★**「屏幕实测 / 有效缩放」一律按需实时读**（`uiSz.live`），**绝不放进 `uiScanOne`** —— 那是每刷新对**全部条目**跑的（深挖视图可到几千条），多读 5 个方法就是整块变慢。取证 = `/edb sz [N]`（别名 `/edb 尺寸`；★**不叫 size** —— `/edb size W H` 是「改画布尺寸」）+ 有界存档环 `EH_DEBUGBOX_CFG.sizeProbe`(40)。判据 = `tmp/dbx_size_harness.js`（56 条）+ `tmp/dbx_size_mutate.js`（10 变异全抓）。
- ★★★**图层树的层级只能来自「扫描时写下的层号」**，不许数路径里的 `/`（缩进与层深过滤同一口径）；折叠 `ui.treeCollapsed[路径]` 落存档；层深唯一写入点 `uiDepthApply`（`0` = 一个标记都不清）。判据 `DBX TREE WIRING CHECK` + 组 205；**R15 ④**。★**默认档**（用户 1.75.36 截图定稿）= 扫描源 `SCAN_SRC_DEFAULT`（`"ui"` = **界面/UIParent，不是地图**）+ 层深 **1**；只有**未交互过**才走默认，点过任一扫描源后**完全按勾选**（空集 = 一个源都不扫）。
- ★★★**「算出来却写进一个从没被创建过的控件」= 静默死代码**：`if ui.X then` 守卫让「控件名写错」与「条件不满足」长得一样 ⇒ ① 写完 UI 文案先问「这个控件存在吗」；② 这类坑行为断言照不到 ⇒ 用源码检查钉（凡被写入的句柄都要有**赋值点**）。
