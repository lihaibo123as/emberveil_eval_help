## 1.74.34-26（真机红字修复：不能被索引的对象不许打断刷新）

- **用户截图（实机红字）**：
  `Interface\AddOns\EH_DebugBox\EH_DebugBox.lua:2377: attempt to index field 'f' (a userdata value)`
  调用链 `uiScanState ← uiRefresh ← markDragEnd ← uiMarkDragStop`（拖一下标尺就炸）。
- **根因**：本客户端 **frame/region 的 userdata 并非都有 `__index` 元表**，而且 `type()` 还骗人（返回 "table"）——
  `if type(e.f.IsShown) == "function"` 这种「直接索引」在**个别对象**上会**抛错**，把整次刷新打断
  （列表停更 + 红字弹窗）。1.74.34-25 让更多纹理/子件进了列表 ⇒ 这个一直潜伏的写法第一次撞上了坏对象。
- **改法（两层）**：
  1. **安全字段读口 `uiField(obj, k)`**（`pcall(function() return obj[k] end)`，读不到 = 当它没这个方法）：
     `uiFrameName` / `nodeType` / `uiRelName` / `uiIsRegionObj` / `uiScriptHit` / `uiBuildEntries` 的 `scaleable` 判据 /
     `/edb named` 的类型读，以及 `SetScale`/`SetAlpha`/`SetWidth`/`SetHeight`/`ClearAllPoints` 那些调用点全部改走它。
  2. **条目级 pcall 兜底**：`uiScanState` 的循环体抽成 `uiScanOne(e)`，逐条目 `pcall`；
     坏条目（连 `IsShown` 都索引不了）**如实记名**：`ui.badEntries` + 落档 `EH_DEBUGBOX_CFG.badEntries` +
     限频播报（不静默、也不假装扫全），其余条目照常刷新。
- **回归哨兵**：组 203⑦ 造一个「索引即抛错」的对象塞进地图树，走真入口 `/edb scan` 断言
  ① 扫描不被它打断 ② 坏条目被如实上报 ③ 其余条目照常刷新（此哨兵当场抓到 `uiBuildEntries` 里的 `type(nd.f.SetScale)`，已一并修）。
- 闸门：`node luacheck.js` SYNTAX OK · `node test_engine.js` ALL TESTS PASS。

## 1.74.34-25（「纹理信息看不见」修复：判据只看名字 + 区域行显示真名）

- **用户报**：「子插件 图层调试工具 在加了可见性功能之后一些图层纹理信息就看不见了，
  **即使选了全部也是**」（附截图：`结果 1`、过滤行 `可见性:全部 · … · 隐藏无名 · 层深:2`，列表只剩 `[顶层] WorldMapDetailFrame`）。
- **定位（读代码定案，不是猜）**：
  - `uiFiltered` 里 **可见性:全部 = 不过滤**（`visOn` 为真但 `onlyVis == nil` ⇒ `okVis` 恒真）⇒ **可见性不是元凶**。
  - 元凶是 **`uiEntryNamed`**：旧判据把「是不是**区域层**」当成「有没有名字」——
    `e.named = ((not e.isRegion) and nm ~= nil and …)`，而**一张纹理永远是区域层** ⇒
    「隐藏无名」一开，**有真名的纹理**（`WorldMapDetailTile1..12` / `WorldMapOverlay1..9` / `WorldMapHighlight`）
    也一起被藏掉。而 `DBX_NAMED_TIP`（三语言）一直对用户承诺的是「**GetName() 为空**的才隐藏」——
    即**实现比文案更严**，不是需求变了。
  - 顺带抓到**第二半原因**：`scanTree` 给区域拼的路径段**一律**用对象类型（`region:Texture`）⇒
    有真名的纹理在列表里也只显示「纹理:Texture#7」，即使看得见也**认不出是哪个贴图**。
- **改法**：
  1. `uiEntryNamed`：判据收敛成一句 **「有名字、且不是合成名」**（与区域/帧无关）——
     合成名（贴图路径_0x地址）与 GetName 为空的两类照旧被藏（1.74.31 那次修复的成果不丢）。
  2. `scanTree`：区域段**有真名就用真名**（`region:WorldMapDetailTile3` → 列表显示「纹理:WorldMapDetailTile3」），
     无名/合成名的照旧退回类型名（`region:Texture` + `#n`，老存档键格式不变）。
  3. 三语言 `DBX_NAMED_TIP` 补上「合成名（贴图路径_0x地址）也会被藏；**有真名的纹理照常列出**」。
- **断言**：组 203 夹具的「区域·居然有真名」改成 `named = true`，并加两条正向哨兵
  （**有真名的区域层必须在列表里** + **行里显示的是它的真名**）；`badRows` 的判据从「是区域层」改成
  「叶子名是通用名 `纹理:Texture`/`字体串:FontString`」或「含 `_0x`」；无名计数 5 → 4。
- 闸门：`node luacheck.js` SYNTAX OK · `node test_engine.js` ALL TESTS PASS（组 203 打印：
  「开关=开 → 列表 2 条（混入 0 条）· 开关=关 → 列表 9 条」）。

## 1.74.34-20（自动适配「没效果」修复：闸门放错 + ticker 起得太晚）

- **用户报**：自动模式没效果；并问「打开地图是否要等渲染完成才能执行命令」。⇒ 两处都改：
  1. **闸门放错（主因）**：1.74.34-19 的自动 tick 复用了「**贴图载入完成**」那道闸门（`uiDetailTilesReady` 要求
     **每一张**纹理 `GetTexture()` 非空）。那道闸门是给**缩放**用的；**适配几何只需要能读写几何**，
     而只要有**一张**纹理引擎不报路径，这扇门就**永远不开** ⇒ 自动永不执行。现改为：
     **开图 + es≠1 + 幂等判据不匹配** 就动手（0.5s tick；客户端重排后下个 tick 自动补上）。
  2. **ticker 起得太晚**：原来只在事件帧（PLAYER_ENTERING_WORLD / VARIABLES_LOADED）里起；
     现在**文件期也试起一次**（`pcall(mapFitTickEnsure)`），事件期再兜一次。
- **取证（新增）**：ticker 每 2s 写一次闸门快照 `EH_DEBUGBOX_CFG.mapFitGate`（开关/地图开/es/ticker 是否在/原值条数），
  并有 **`/edb maptile diag`**（立刻诊断 + 落档 + 顺手试改一次）。
- **回答用户的问题**：命令随时能跑；但**写进去的几何会被客户端随后的布局覆盖** ⇒ 要么等它稳定，
  要么像现在这样**持续幂等补写**（已选后者，所以不必等渲染完成）。

## 1.74.34-6（严重事故修复：全屏点击全废 —— 拖拽支撑块插错了词法位置）

- **事故（用户急报 + 红字截图 `1636: attempt to call upvalue (a nil value)`）**：1.74.34-5 的拖拽支撑块
  （`local uiMarkDragStop, uiMarkPlaceFrom` / `markDragActive` / 全屏接盘）**误插在 `uiMarkGet` 函数体内** ⇒
  ① 这些 local 每次调用都是**新槽位**，而顶层（文件作用域）的赋值写的是**全局** ⇒ 处理器里的 upvalue 恒 nil，一帧一炸；
  ② 炸之前 `uiMarkCatcherShow(true)` 已把**全屏接盘**放了出来，收尾路径又全炸 ⇒ 接盘永远不收，
  **吃掉整个屏幕的所有点击/拖拽**（用户报的「整个屏幕的窗口功能都无法使用」）。
- **修法**：支撑块整体移到 `uiMarkGet` **之前**（文件作用域）——正是本项目铁律
  「跨段共享件一律放在所有使用方之前 / local 声明顺序 = 词法作用域」的又一次实踩。
- **教训（写入判据）**：往**函数体内**插共享件 = 等价于没插；插入前先确认落点是**文件作用域**还是某个函数体内；
  全屏遮罩/接盘类控件，「显示」和「一定能收回去」必须成对审查（收不回去 = 全屏瘫痪）。

## 1.74.34-5（地图标记拖拽漂移根治：方案 A + 方案 B，用户拍板全做）

- **根因（三条全中主仓 `tools/DragFrames.lua` 已定案的坑）**：
  ① 旧 OnUpdate **每帧回读 `GetPoint` 加增量** → 本客户端偏移口径有歧义，误差留在锚点里逐帧叠加（越拖越偏）；
  ② 位移 `(cx)/es` **除缩放** → 缩放 ≠ 1 的层按比例算错；③ 结束只有信息条自己的 `OnMouseUp` 一道 → 松手事件一丢就「跟手不放」。
- **方案 A（治①②）**：新增 `uiMarkPlaceFrom(f2, from, totX, totY)` —— 位移按**屏幕**算（不除缩放）；
  拖前快照（实测屏幕位置+缩放+拖前锚点，`markDragBegin` 改为**返回**快照）+ 光标**累计**位移 →
  首猜 ÷缩放 → SetPoint → **量回自证** → 手量折算修正（≤3 轮）；位移没变（<0.5px）不重写锚点防闪。
- **方案 B（治③，兜底）**：新增全屏接盘 `EH_DB_MARKCATCHER`（FULLSCREEN_DIALOG/800，仅拖拽期间 Show），
  **松手在游戏窗口任意位置都能结束拖拽**；再加指针静止 ≥1.5s / 拖拽 ≥30s 强制结束保险；
  收尾唯一入口 `uiMarkDragStop`（清状态 + 藏接盘 + `markDragEnd` 落存档，存档口径不变）。
- **真机验证**：`/reload` → 对某层设透明（出信息条）→ 快拖/慢拖/拖出条外松手 → 层 1:1 跟手、松手即停、再拖不叠加 → `/reload` 后位置保持。

## 1.74.34（图层调试面板：报错修复 + 选中深挖扫描 + 单选/多选分家 + 底部布局）

### 修复 1+2：点树箭头弹红字 `bad argument #1 to 'rawget' (table expected, got userdata)`

- **根因（两轮真机截图定案）**：
  ① 第一轮：本客户端的帧是 userdata，`rawget(row, "entry")` 只接受 table → 折叠开关（▼/▶）一点就炸，永远走不到 `uiTreeToggle`（= 用户报的「下箭头无法点击」）。
  ② 第二轮（更隐蔽）：修了守卫之后**依然炸**——本客户端 `type(帧)` 居然报 `"table"`，但 `rawget` 的 C 侧仍按 userdata 拒绝 ⇒ **type() 不能当分路判据**。
- **修法**：新增唯一入口 `uiRowEntry(row)`——**让 rawget 自己说话**：`pcall(rawget, row, "entry")`，失败再退到 `pcall` 读字段（本客户端允许帧挂自定义字段，`uiRefresh` 就是 `row.entry = e` 写进去的）。行 OnClick / 多选框 / 折叠开关三处共用。
- **连带发现（第二次截图的堆栈）**：点 ▶ 的堆栈里出现的是**行本体**的 OnClick ⇒ 本客户端点子按钮（折叠开关/多选框）会**连带触发**行 OnClick。
  修法：行 OnClick 开头加焦点守卫——`GetMouseFocus()` 是 `tw` 或 `rchk` 时行不动作（否则点 ▶ 会顺带把选择清单清成单选、点多选框会被行点击清场）。

### 修复 3：「扫描」在有选中目标时 = 只深挖选中目标的子树

- 不再全量重枚举所有根（省性能）；`scanTree` 深度上限 4 → 深挖走 64 + 节点上限 20000（超限**如实报**，不假装扫全）。
- 深挖根**保留原路径** ⇒ 选中/自定义/折叠等按键记录全部沿用；挖完「层深」自动 = 2（走 `uiDepthApply` **单入口**，根 + 下一级直接可见）。
- 选中下一级再点「扫描」可一轮轮无限往下挖；**清空选择再点「扫描」= 回到全量**。
- `uiBuildEntries(skipExtra)`：深挖视图不追加 `[顶层]`/`[全局]` 额外条目。

### 修复 4：层选中 = 行点击单选 / 左侧多选框多选

- 点层单元 = **单选**（清掉其它选择；再点已单选的同一层 = 取消）；多选只走左侧多选框（勾选/取消互不影响）。

### 修复 5：底部菜单布局遮挡（用户截图 2）

- 「层深:N」压住「扫描」：旧代码 `pcall(uiTopTake, depthBtn, 78)` 把**按钮本体**当宽度传给排布游标 → 算术炸在 pcall 里 → depthBtn **从没 SetPoint**（无锚点帧落左下角）。现改放底部第四排「扫描」右侧（BOTTOMLEFT 76,8）。
