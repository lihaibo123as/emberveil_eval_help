### 1.1 两种频道 = 两套发布通道（脚本自动识别）

| 频道类型 | 发布方式 | 脚本行为 |
| --- | --- | --- |
| `type=1` 文字频道 | `POST /message/create`（type=10 卡片） | 自动 |
| `type=4` **帖子频道** | `POST /thread/create`（`title` + `content`=卡片 JSON）—— **普通 message/create 发不进去** | 自动（真发前先读 `channel/view` 判断类型） |

帖子频道专属注意：主楼内容用**卡片格式**；帖子有审核状态 `status`（1 审核中 / 2 通过 / 3 编辑审核中），脚本会把 `status` 打出来。若卡片里的 `file` 模块在帖子主楼不被支持，用 `--mode link` 退路（只发文字 + 发布页链接，不附包）。

## 2. 接口链路（为什么必须两步）

```
① POST /api/v3/asset/create     （multipart/form-data，字段名 file，二进制）
        → { "url": "https://img.kookapp.cn/attachments/…/EvalHelp-v1.75.110.zip" }
② POST /api/v3/message/create   （type=10 卡片消息，content = 卡片 JSON 字符串）
        卡片里每个包一个 file 模块：{ "type":"file", "src":"<①的 url>", "title":"…" }
```

两条官方硬性规则决定了**不能省掉第 ① 步，也不能直接把本地文件塞进消息**：

- 「发送的图片必须由你的机器人上传，否则将失败，并提示**找不到资源**。此规则对视频消息也适用。」
- 「一个资源在被上传之后默认是处于**不可见状态**的，只有当他作为卡片的内容以正确的形式被发送出去才是可见的，比如图片作为 `image` 元素、**文件附件作为 `file`** 等；如果仅仅是作为 KMarkDown 的文字内容的一部分，是不会刷新其可见状态的。」

⇒ 所以实现是「**先 asset 上传拿 url，再用卡片 file 模块把它发出去**」。
一条卡片最多 5 个 card / 合计 50 个 module ⇒ **所有包可以一条消息发完**（当前 1 主 + 4 子插件 = 5 个 file 模块，远没到上限）。

**备选通道**（`--mode file`）：每个包发一条 `type=4` 文件消息（`content` = 那个 url）。留作卡片 `file` 模块万一不对劲时的退路（**首次真机请先用卡片模式验证，失败再切**）。

## 3. 前置条件（缺一条就会失败）

| # | 条件 | 怎么确认 |
| --- | --- | --- |
| 1 | **机器人在这个服务器里** | 开发者后台 → 机器人 → **「邀请链接」**，在 KOOK 客户端用有管理权限的账号打开并授权（机器人已开「公共机器人」⇒ 任何人可加）。**判据 = `--check` 打印的「机器人所在服务器」非空**。★实测坑：`guild/view` **不能**用来判断成员关系（机器人不在服务器时它照样返回频道/角色）；`guild/list` 才是真判据；`guild/user-list` 会回 `code=40000 该用户不在该服务器内`（**HTTP 200 但 code≠0**，别只看状态码）。 |
| 2 | **机器人能看到目标频道** | 频道权限里给机器人角色「查看文字、语音频道」（bit11 = 2048） |
| 3 | **机器人能发消息 / 发帖** | 「发布消息」（bit12 = 4096）；发**文件**建议再给「上传文件」（bit14 = 16384）；帖子频道还要能「回复帖子」（bit29 = 536870912，帖子频道相关） |
| 4 | **bot token 就位** | 写进仓库根 `token/kook.txt`（`.gitignore` 已忽略 `/token`）或设环境变量 `KOOK_TOKEN`；**绝不提交、脚本永不打印** |
| 5 | **打包产物是本版的** | 见 §5：脚本会**现读 `.toc` 版本**去核对包名，缺包直接拒绝发送 |

## 4. 用法

```powershell
# ① 只读自检（推荐第一次就跑）：确认 token 是谁、机器人在不在服务器、频道对不对、权限位够不够
cmd /c "node kook\kook_publish.js --check"

# ② 演练（默认行为，不发任何请求）：列出将上传的包 + 打印将发出的请求 + 卡片结构
cmd /c "node kook\kook_publish.js"
cmd /c "node kook\kook_publish.js --print-card"      # 额外把卡片 JSON 打出来看

# ③ 真发：上传 asset → 一条卡片消息（全部包）
cmd /c "node kook\kook_publish.js --send"

# 备选通道：每个包一条文件消息
cmd /c "node kook\kook_publish.js --send --mode file"

# ④ 频道查重（只读）：同一插件 + 同一版本的帖只留最新创建的那条（见 §4.3c）
cmd /c "node kook\kook_publish.js --dup-audit"
cmd /c "node kook\kook_publish.js --dup-prune"             # 只看「待删清单」（不发请求）
cmd /c "node kook\kook_publish.js --dup-prune --send"      # 真删（不可恢复；清单须与上一条逐条相同）
```

> ⚠️ 本机踩到一次沙箱限制：PowerShell 里直接 `node kook\kook_publish.js` 会被拦（`node.exe … Access is denied`），**用 `cmd /c "node …"` 包一层就正常**。这是执行环境的问题，不是脚本的问题。

参数一览：

| 参数 | 作用 |
| --- | --- |
| `--check` | 只读自检（token 身份 / 机器人在服 / 目标频道 / 权限位预估） |
| `--send` | 真发（**默认不发**） |
| `--print-card` | 演练时把卡片 JSON 打印出来 |
| `--mode card\|file` | 卡片模式（默认）/ 每包一条文件消息 |
| `--dir <目录>` | 覆盖打包产物目录（默认取 `config.json` 的 `pack_dir`） |
| `--files a.zip,b.zip` | 手工指定要发的包（跳过「按 toc 现算包名」的核对，用于补发/试发） |
| `--assets versioned\|both` | **默认 `versioned`：只发带完整版本号的包**（用户 2026-10-09 定）；`both` 才会连固定名包一起发 |
| `--thread-view <id>` | 回读某条帖（`status` / 分区 / 封面 / `medias`） |
| `--thread-delete <id> --send` | 删某条帖（不可恢复） |
| `--thread-list` / `--dup-audit` | **只读**：列出频道全部帖子 + 查重结论（`thread/list` 端点，2026-10-10 首次实测） |
| `--dup-prune [--send]` | 删「同一插件 + 同一版本」的旧帖，**只留最新创建的那条**（不带 `--send` = 只看清单） |
| `--title <标题>` | 覆盖卡片标题（默认 `EvalHelp v{ver} 发布`） |
| `--notes <文件>` | 临时用指定文件当更新文案 |
| `--notes-auto` | 看「自动摘要」长什么样（调试用） |
| `--no-notes` | 本次完全不附更新文案 |
| `--json` | 机器可读输出（给上层脚本用） |
| `--min-interval <ms>` | 请求最小间隔（默认 400ms；限流自适应见下） |

## 4.1 发布包口径（用户 2026-10-09 定）

**只发带完整版本号的那份**：`EvalHelp-v1.75.110.zip` + 每个子插件的 `EH_xxx-vX.Y.Z.zip`。
固定名那份（`EvalHelp.zip` 等）**默认不发** —— KOOK 里每次都是新消息，固定名没有意义。想改才用 `--assets both`。

## 4.2 更新文案 = 按插件分段的**概要**（用户 2026-10-09 定：「需要总结，不要做版本流水账记录」+「概要记录每次插件发布的修改」）

`kook/notes/<版本>.md` 用 **`## 插件名` 分段**；每条帖**只显示它自己那几个插件的段落**（首个 `##` 之前的内容 = 整体开场，只进第一条帖）。**每个插件写 1~2 条要点**。

```markdown
**本次更新要点**

## EvalHelp
- **一键宏新增「取消跟随」**：技能编辑的「角色行为」里可以配一条，用来断掉游戏自带的自动跟随。
- **新增「队伍 / 团队宠物」条件族（8 个条件）**：可按队友宠物的血量 / 光环 / 数量出招，也能把它选成目标。

## EH_Bag
- **修复整理特殊袋子时的卡死**：箭袋 / 附魔 / 草药 / 灵魂袋不再陷入来回搬运。
- **修复背包条拖拽与换包**。
```

文案的取用优先级（脚本内唯一实现 `resolveNotes()` + `notesForPost()`）：

| 优先 | 来源 | 说明 |
| --- | --- | --- |
| ① | **`kook/notes/<版本>.md`（按插件分段）** | **推荐**：release 时写好的**对外概要**，按插件分段落 |
| ② | 同文件但**未分段** | 整段只放进**第一条帖**（控制台会提示建议分段） |
| ③ | 自动摘要（退路） | 只抽 CHANGELOG 该版本段的**标题行**，滤掉「带版本号的行」与「内部口吻词」（判据/交付/真因/调研/探针/存档/闸门/收口/接线…）⇒ 常常只剩 2~3 条；只进第一条帖，**控制台警告「建议手写」** |
| ④ | `--no-notes` | 本次不附文案 |

`config.json` 的 `notes_fallback`：`"auto"`（默认，用③）/ `"none"`（没有手写文案就**干脆不附**）。`--notes <文件>` 可临时换一份。

**对外文案的写法（铁律）**：

- **写「玩家能得到什么」**，不写「我们内部怎么修的」。
- **禁止版本流水**：不写「本版跨越 v1.75.106 → v1.75.110」、不写「0.2.28~0.2.36 六连」这类按版本罗列。
- **禁止内部术语与路径**：`addons\EH_Damage\CHANGELOG.md`、`CTG_7`、`判据`、`闸门`、`探针`、`真因`、`存档键` 等一律不出现。
- **每个插件 1~2 条**，每条一句话、动词开头；细节留给 GitHub/Gitee 发布页。
- 某个插件本版没改动 ⇒ **直接不写它的段落**（脚本会自动跳过；版本号仍出现在卡片头部的版本行里）。

范例：`kook/notes/1.75.110.md`

> 每次 release 时**先写 `kook/notes/<版本>.md`，再跑 `--send`** —— 否则发出去的会是自动摘要（或者第二条帖什么都不附）。

## 4.3 发布帖拆分 = 按插件分类进各自分区（用户 2026-10-09 定：「将插件自动发布包对应插件分类内」）

`config.json` 的 `posts[]` 定义一版发布拆成几条帖（**现行 = 一个插件一条帖**，主插件 1 + 每个子插件各 1）：

| 帖 | 分区 | 带的插件 | 标题模板 |
| --- | --- | --- | --- |
| 主插件 | 战斗 `15785972` | EvalHelp | `EvalHelp v{ver} 发布（主插件 · 全职业工具）` |
| EH_Damage | 战斗 `15785972` | EH_Damage | `EH_Damage v{sub} 发布（增强伤害显示）` |
| EH_DPS | 战斗 `15785972` | EH_DPS | `EH_DPS v{sub} 发布（队伍伤害统计）` |
| EH_DebugBox | 战斗 `15785972` | EH_DebugBox | `EH_DebugBox v{sub} 发布（图层调试）` |
| EH_Bag | 背包 `15785973` | EH_Bag | `EH_Bag v{sub} 发布（整合背包）` |

- 每条帖 = 一次 `thread/create`（各带自己的 `category_id`），帖内只放**它自己那几个插件**的包与概要段落。
- 标题占位符：`{ver}` 主插件版本 · `{sub}` 本条帖第一个子插件的版本 · `{names}` 插件名列表。
- ★**两条守卫**：**要发的**插件没被任何帖认领、或**被两条帖重复认领** ⇒ 脚本**直接拒绝发送**（防止漏发包 / 重复上传）；**本版没变化的**插件没被认领 ⇒ 只提示一句（不拦发布）。
- 删掉 `posts[]` ⇒ 退化成「一条帖装全部」，分区取 `category_id`。

### 4.3b 无版本变化的帖不发（用户 2026-10-10 定：「将无版本变化的子插件无需发布到 kook」）

- **判据**：某条帖的插件**全部与「上一次发布」同版本** ⇒ **这条帖不发**（频道里不留「本版无改动」的水帖）。
- **基线取值**：`kook/state/releases.json` 里**版本号 ≠ 本版**的最新一条（按版本号比大小，不靠时间戳）；老记录没有 `plugins` 映射 ⇒ 从包名 `<名>-v<版本>.zip` 现推。
- ★**判不出就发**（没有历史记录 / 基线里没有这个插件 ⇒ 视为有变化）—— 少发一次玩家就永远看不到。
- ★**同一版本重跑 = 只补没发成的帖**：已发过的（按记录里的 `threads`）不重复发，上次判定「无变化」的继续跳过，其余补发；**整版重发** = 先 `--thread-delete` 删掉帖 + `--all-posts`。
- **强制全发**：命令行 `--all-posts`（别名 `--no-skip`）· 或 `config.json` 的 `skip_unchanged_posts: false`。
- dry-run 会打印**版本判定块**（每个插件「现读版本 / 基线版本 / 有变化还是无变化」+ 发几条帖 / 跳过哪几条）。
- 判据 = `node tmp/kook_skip_check.js`（真跑 dry-run 六个场景；脚本自己备份并**逐字节还原** `releases.json`/`config.json`）⇒ **`KOOK SKIP CHECK OK`**。
- ★★★**这条闸门只在「统一推送」时跑 —— release 期间不跑**（用户 2026-10-10 定：「**release 不跑 ./tmp 测试**」）：发布时看判定块就走**产品自己的只读/演练命令**（`--check` · 不带 `--send` 的 dry-run · 收尾 `--dup-audit`）。

### 4.3c 重复版本查重：同一插件 + 同一版本只留最新（用户 2026-10-10 定：「排查 kook 内存在的重复版本的子插件，保留最新的」）

- **判据**：帖子标题里的 `<插件名> v<版本> 发布` ⇒ **同一插件 + 同一版本**出现多条 ⇒ 只留**最新创建**（`create_time` 最大）的那条，其余删。
- ★**不同版本不算重复**（EH_Damage `0.2.36` 与 `0.2.43` 两条都留）；**标题认不出我们模板**的帖**一个字节都不动**，只如实列出。
- ★**不可恢复**：先跑 `--dup-prune`（不带 `--send`）看清单，两次清单**逐条相同**再 `--dup-prune --send`。
- ★**删完只给记账加标记**（`releases.json` 补 `deleted: true` / `deleted_at`，`markThreadsDeleted()`）—— 保留「哪一版发过什么」，也保住下一次比版本的基准。
- **与 §4.3b 的分工**：§4.3b「无版本变化的帖不发」**只防将来产生重复**；本节清**历史重复**与 `--all-posts` 重跑造成的重复。
- 本次清理（2026-10-10）：频道 10 条 ⇒ 删 v1.75.110 的 4 条重复子插件帖 ⇒ 现役 **6 条**；`--dup-audit` 复核 `✅ 没有发现「同一插件 + 同一版本」的重复帖`。全文与锚点 = `CLAUDE.md` §二·补。

**限流**：每次请求都会打印 `x-rate-limit-remaining/limit/reset/bucket`；撞到 429 会按 `Reset + 1s` 自动等待重试，**连撞 3 次就主动中止**（官方明确多次超速可能禁用 bot，脚本不替你冒险）。

### 4.4 封面与正文配图（用户 2026-10-09 定）

- **图源 = 该帖插件自己的 `./preview`**：主插件 `preview/`，子插件 `addons/<名>/preview/`（实测全是 png ⇒ 满足卡片 `image` 的 jpeg/gif/png 限制）。
- **配置**：`posts[].cover`（封面文件名）· `posts[].images`（正文配图文件名列表）；不写就自动挑（`preview.prefer` → mtime 最新，上限 `preview.max_per_post`）。
- **链路**：每张图先 `POST /asset/create` 上传拿 url → 卡片加 `image-group` 模块（正文配图）→ `thread/create` 带 `cover`（封面）。
- ★**封面必须同时出现在正文配图里**：官方规则「资源上传后默认不可见，只有作为卡片图片元素发出去才刷新可见状态」⇒ 只传 `cover` 参数可能不显示。
- 判据（回读 `thread/view`）= **`cover` 非空** 且 **`medias` 里有对应数量的 `type:2` 图片条目**。

## 5. 「缺包守卫」——为什么它拒绝发旧包（本机实测）

脚本**不接收版本号参数**，而是现场读 `EvalHelp.toc` 与 `addons/*/*.toc`，再按 `<名>-v<版本>.zip` 去产物目录找。找不到就直接失败，并列出目录里「包名版本 ≠ toc 版本」的过期包。

本机 2026-10-09 实测（**当前产物确实是旧的**）：

```
✘ 缺包（先跑打包脚本，别发旧包）：
   EvalHelp-v1.75.110.zip
   EH_Damage-v0.2.36.zip
   目录里下列包的版本号与 .toc 现读版本不一致 ⇒ 打包没重跑：
     EH_Damage-v0.2.26b.zip（包名 0.2.26b ≠ toc 0.2.36）
     EH_Damage-v0.2.27.zip（包名 0.2.27 ≠ toc 0.2.36）
     EvalHelp-v1.75.35.zip（包名 1.75.35 ≠ toc 1.75.110）
```

⇒ **发之前必须重跑打包**（否则会把 1.75.35 的包当 1.75.110 发出去）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tmp\pack_subaddons.ps1
# 主插件的打包脚本按当前版本同理（历史范式：tmp\pack_<版本>.ps1，输出到游戏 AddOns 目录）
```

## 7. 首次真发要重点看什么（这些是还没被验证过的）

| 待验证 | 看什么 | 不对怎么办 |
| --- | --- | --- |
| 卡片 `file` 模块是否真的渲染成**可下载附件** | 频道里那条消息：应能看到 5 个文件条目 | 切 `--mode file`（type=4 文件消息，官方最经典的用法） |
| 上传文件**大小上限**（官方未文档化） | 主插件包约 1.5–1.8 MB，若 `asset/create` 报错即为上限问题 | 压缩包 / 分包 / 改用「发布页链接 + 只发小包」 |
| `asset/create` 的**限流桶** | 打印出来的 `bucket=` 与 429 时机 | 调大 `--min-interval` |
| 频道级权限**是否被覆写收紧** | `--check` 的权限位是**服务器级**的估值；官方没有「最终生效权限」接口 | 直接把「查看/发布/上传」三个位给足，或先手工在客户端发一条试 |
| 机器人发的消息是否需要**先上线** | `--check` 会打 `user/get-online-status` | 若要求在线：用 webhook 模式时需调 `user/online` |

## 8. 排错速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `⚠⚠ 机器人不在目标服务器里` / `guild/list` 为空 | 机器人还没被邀请进服务器 | 开发者后台 → 机器人 → 邀请链接 → 客户端里授权（`guild/view` 有数据≠在服务器里！） |
| `code=40000 message=该用户不在该服务器内`（可能配 HTTP 200） | 同上；也可能是 `filter_user_id` 查的不是本服成员 | 判成功一律看 `code`，别只看 HTTP 状态 |
| `HTTP 403 你没有权限进行此操作`（`guild-role/list`） | 机器人没有「管理角色权限」(bit10) | 不用理它：脚本已改为读 `guild/view.roles` |
| `code=… message=找不到资源` | 消息里的文件 url 不是本机器人上传的（或把 url 当 KMarkdown 文本发） | 走 asset 上传 + 卡片 file 模块（本脚本已如此） |
| 帖子发出去但频道里看不到 | 帖子 `status=1` 审核中 | 客户端里放行；脚本会打印 status |
| `✘ 找不到 KOOK bot token。任选一种：…` | token 没就位 | 写 `token/kook.txt` 或设 `KOOK_TOKEN` |
| `✘ 缺包（先跑打包脚本，别发旧包）` | 产物是旧版 | 重跑打包（§5） |
| `HTTP 429` 反复出现 | 触到限流桶 | 脚本已自动退避；连撞 3 次会中止，等 `Reset` 后再跑 |
| 消息发出去了但**频道里看不到** | 频道权限（bit11 查看 / bit12 发布）不够，或机器人在该频道被单独 deny | 用 `--check` 看权限位；必要时在频道权限里给机器人角色放行 |
| 卡片发不出去、`--mode card` 一直失败 | 卡片结构被拒 | 切 `--mode file` 先保通路 |
