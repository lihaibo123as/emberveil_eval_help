## 1. 接入基础【已核实】

| 项 | 值 |
| --- | --- |
| BaseUrl | `https://www.kookapp.cn/api` |
| API 版本 | 路径内指定：`/api/v{version}`，当前**只有 v3**（默认） |
| 鉴权 | 请求头 `Authorization: TOKEN_TYPE TOKEN`，机器人用 `Bot`，OAuth2 用 `Bearer`；例：`Authorization: Bot BHsTZ4232…` |
| 取数 | **GET**（所有「向服务器拿数据」） |
| 提交 | **POST**（默认 JSON body，需 `Content-Type: application/json`） |
| 本地化 | 可选请求头 `Accept-Language: en-US`；不支持时回落 `zh-cn` |
| 返回信封 | `{ "code": 0, "message": "操作成功", "data": … }`，`code=0` 为成功，非 0 为失败 |
| 分页通用参数 | `page`、`page_size`（默认 50，常规最大 50）、`sort`（如 `-id` 表示按 id 降序） |
| 分页通用返回 | `items`、`meta{page,page_total,page_size,total}`、`sort` |
| 额外字段警告 | 官方明确：接口可能返回**文档未列出的字段**，请只依赖文档字段（未文档字段可能随时变更） |

### 1.1 错误码这件事（文档缺口）

- 官方在接口规范里写「具体的错误码参见**错误码一览**」，但：
  - 该文字在页面上**不是超链接**（实测 DOM 中不存在任何含「错误码」的 `<a>`）；
  - 文档站**没有错误码页**（实测该页 49 个唯一链接全量枚举，其中 44 个是 `/doc/…`，**没有一个包含 error**）；
  - 猜测路径 `https://developer.kookapp.cn/doc/error-code` 实测 **HTTP 404**。
- ⇒ **工程含义**：错误分类**不能依赖文档化的错误码表**，只能：
  1. 用 `code` + `message`（`message` 受 `Accept-Language` 影响）在运行时**采集并落盘**，自建错误码字典；
  2. WS 层另有**信令级**状态码（见 §8.4，那部分官方是有表的）。

## 2. 频道对象与类型

### 2.1 `channel/view` 的完整字段【已核实】

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 频道 id |
| `guild_id` | string | 服务器 id |
| `user_id` | string | 频道创建者 id |
| `parent_id` | string | 父分组频道 id |
| `name` | string | 频道名称 |
| `topic` | string | 频道简介 |
| `type` | int | **`0` 分组、`1` 文字、`2` 语音**；★**实测还有 `4` = 帖子频道**（2026-10-09 在用户服务器实测到，见 §13） |
| `level` | int | 频道排序 |
| `slow_mode` | int | 慢速限制（**单位见 §2.3 的矛盾点**） |
| `has_password` | boolean | 是否已设置密码 |
| `limit_amount` | int | 人数限制 |
| `is_category` | boolean | 是否为分组类型 |
| `permission_sync` | int | 是否与分组频道同步权限 |
| `permission_overwrites` | array | 针对**角色**的频道权限覆盖 |
| `permission_users` | array | 针对**用户**的频道权限覆盖 |
| `voice_quality` | string | `1` 流畅 / `2` 正常 / `3` 高质量 |
| `server_url` | string | 语音服务器地址，`HOST:PORT/PATH` |
| `children` | array | 子频道 id 列表（需 `need_children=true`） |

`channel/view` 参数：`target_id`（必）、`need_children`（可选，默认 false）。

### 2.2 `channel/list` 的字段是「精简版」【已核实】

| 字段 | 说明 |
| --- | --- |
| `id` / `user_id` / `parent_id` / `name` / `type` / `level` / `limit_amount` / `is_category` | 仅此 8 个 |

- **没有** `topic`、`slow_mode`、`permission_*`、`voice_quality`。
- 参数：`guild_id`（必）、`type`（可选，`1` 文字 / `2` 语音，**默认 1**）、`parent_id`（可选，父分组 id）、`page` / `page_size`。
- ⚠️ `type` 有默认值 `1` ⇒ **不传 `type` 就只拿到文字频道**，分组（`type=0`）与语音频道（`type=2`）会被漏掉。一个「拿全部频道」的实现必须**分别按 type 取，或直接用 `guild/view`**。

### 2.3 文档内部矛盾点（必须实测，别猜）

| 矛盾 | 说法 A | 说法 B | 影响 |
| --- | --- | --- | --- |
| `slow_mode` 单位 | `channel/view`：**单位秒**；`objects`：**单位为秒(s)** | `channel/update`：**单位 ms**，且给出枚举 `0, 5000, 10000, 15000, 30000, 60000, 120000, 300000, 600000, 900000, 1800000, 3600000, 7200000, 21600000` | 写 5 秒到底该传 `5` 还是 `5000`？读回来是秒还是毫秒？**读→写往返会差 1000 倍**（T3） |
| 分组的 `type` 值 | `channel/view`：`0` 分组 | `objects#频道Channel` 的 type 说明只列了 `1` 文字 / `2` 语音；但 `channel/list` 示例里分组是 `type: 0` | 判定分组请**一律用 `is_category`**，不要用 `type==0` |

### 3.3 创建频道 `POST /api/v3/channel/create`

| 参数 | 必需 | 说明 |
| --- | --- | --- |
| `guild_id` | 是 | 服务器 id |
| `name` | 是 | 频道名称 |
| `parent_id` | 否 | 父分组 id |
| `type` | 否 | `1` 文字 / `2` 语音，**默认 1** |
| `limit_amount` | 否 | 语音频道人数限制，**最大 99** |
| `voice_quality` | 否 | `1` / `2` / `3`，**默认 2** |
| `is_category` | 否 | `1` 是分组 / `0` 否，默认 0。**传 1 时只接收 `guild_id`、`name`、`is_category` 三个字段** |

- 返回：创建成功后的频道信息（结构同 `channel/view`）。
- **无法在创建时设置**：`topic`、`slow_mode`、权限覆写、密码 ⇒ 需后续 `update` / `channel-role/*`。
- ⇒ 建一个「带简介 + 慢速 + 权限」的频道 = **至少 3 类接口、≥3 次调用**。

### 3.4 编辑频道 `POST /api/v3/channel/update`

| 参数 | 必需 | 说明 |
| --- | --- | --- |
| `channel_id` | 是 | 频道 id |
| `name` | 否 | 频道名称 |
| `level` | 否 | 频道排序 |
| `parent_id` | 否 | 分组频道 id，**设置为 `0` 为移出分组** |
| `topic` | 否 | 频道简介，**文字频道有效** |
| `slow_mode` | 否 | 慢速模式，**单位 ms**（值域见 §2.3）**文字频道有效** |
| `limit_amount` | 否 | 最大容纳用户数，**最大 99**，**语音频道有效** |
| `voice_quality` | 否 | `1`/`2`/`3`，**语音频道有效** |
| `password` | 否 | 密码，**语音频道有效** |

- 返回：频道对象（结构见 §2.1 同族，官方示例含 `is_readonly`、`is_private`、`server_type`、`mode`、`is_master` 等**未列入说明表**的字段 ⇒ 【示例推断】，不要依赖）。
- ⇒ **「移出分组」的写法是 `parent_id: "0"`**（字符串 0），不是空串。

### 3.5 删除频道 `POST /api/v3/channel/delete`

| 参数 | 必需 | 说明 |
| --- | --- | --- |
| `channel_id` | 是 | 频道 id |

- 返回 `data: {}`（成功）。
- **没有回收站、没有恢复接口、没有批量删除**。
- **删除分组时子频道会怎样 = 官方未说明**（T4，高危）。

## 4. 频道权限覆写（`channel-role/*`）【已核实】

| 接口 | 方法 | 关键参数 | 说明 |
| --- | --- | --- | --- |
| `/api/v3/channel-role/index` | GET | `channel_id` | 读该频道的 `permission_overwrites` / `permission_users` / `permission_sync` |
| `/api/v3/channel-role/create` | POST | `channel_id`、`type`（`role_id`\|`user_id`，默认 `user_id`）、`value` | 新增一条覆写 |
| `/api/v3/channel-role/update` | POST | 同上 + `allow`、`deny`（默认 0） | 改覆写（`allow`/`deny` 是**权限位整数**） |
| `/api/v3/channel-role/sync` | POST | `channel_id` | 同步分组权限，返回同步后的覆写列表 |
| `/api/v3/channel-role/delete` | POST | `channel_id`、`type`、`value` | 删覆写 |

要点：

1. **`channel_id` 传的是分组 id 时**，`create` / `update` / `delete` 会**同步给所有 `permission_sync=1` 的子频道**（官方原文）⇒ **改一个分组 = 批量改动，风险面很大**。
2. **`type` 默认值是 `user_id`** —— 想写角色权限**必须显式传 `type: "role_id"`**，忘了就是给用户写（或写错对象）。
3. **用户级权限没有独立接口**（`/doc/http/channel-user` 只有 `get-joined-channel` 一个接口）⇒ 用户级覆写也走 `channel-role/*` 的 `type=user_id`。
4. 官方**没有**「最终生效权限」查询接口 ⇒ 机器人实际能不能在某频道发消息，要自己算：**服务器角色位 ⊕ 频道覆写（allow/deny）**，且 `permissions & (1<<bit) == (1<<bit)` 判位；**bit0（管理员）可绕过所有频道权限**。
5. 示例里频繁出现 `role_id: 0`【示例推断】——社区通常理解为 `@全体成员`，但**官方字段说明没有定义它**（T7）。

## 5. 权限位表（unsigned int，31 位）【已核实】

判位公式（官方原文）：
```c
permissions & (1 << bitValue) == (1 << bitValue);
```

| 位 | 值 | 权限 | 备注 |
| --- | --- | --- | --- |
| 0 | 1 | 管理员 | **危险**：绕过所有其他权限（含频道权限） |
| 1 | 2 | 管理服务器 | 改服务器名/区域 |
| 2 | 4 | 查看管理日志 | |
| 3 | 8 | 创建服务器邀请 | |
| 4 | 16 | 管理邀请 | |
| **5** | **32** | **频道管理** | **创建 / 编辑 / 删除频道 —— 频道维护的核心权限** |
| 6 | 64 | 踢出用户 | |
| 7 | 128 | 封禁用户 | |
| 8 | 256 | 管理自定义表情 | |
| 9 | 512 | 修改服务器昵称 | |
| 10 | 1024 | 管理角色权限 | 可创建/编辑/删除低于自己的角色 |
| 11 | 2048 | 查看文字、语音频道 | |
| 12 | 4096 | 发布消息 | |
| 13 | 8192 | 管理消息 | 删他人消息 / **置顶消息（`message/pin` 要求此权限）** |
| 14 | 16384 | 上传文件 | |
| 15 | 32768 | 语音链接 | |
| 16 | 65536 | 语音管理 | **移动 / 踢出语音频道用户** |
| 17 | 131072 | 提及@全体成员 | |
| 18 | 262144 | 添加反应 | |
| 19 | 524288 | 跟随添加反应 | |
| 20 | 1048576 | 被动连接语音频道 | 拥有此**限制**的成员不能主动进语音 |
| 21 | 2097152 | 仅使用按键说话 | |
| 22 | 4194304 | 使用自由麦 | |
| 23 | 8388608 | 说话 | |
| 24 | 16777216 | 服务器静音 | |
| 25 | 33554432 | 服务器闭麦 | |
| 26 | 67108864 | 修改他人昵称 | |
| 27 | 134217728 | 播放伴奏 | |
| 28 | 268435456 | 屏幕分享 | |
| 29 | 536870912 | 回复帖子 | 帖子频道 |
| 30 | 1073741824 | 开启录音 | |

**角色优先级铁律【已核实】**：角色 `position` 值越小越靠前；有管理权限的**只能管理 position 低于（优先级低于）自己的角色/用户**，等于或高于自己的动不了 ⇒ 机器人角色的 `position` 必须足够低（排在管理目标之上），否则会失败。

**一个纯频道维护机器人的最小权限组合（建议）**：
`2048(查看频道) + 4096(发布消息) + 32(频道管理)`；若要置顶说明再加 `8192(管理消息)`；若要管语音再加 `65536(语音管理)`。
**不要给 `1(管理员)`**：它会绕过全部频道权限，一旦脚本出错影响面无法用权限约束。

## 6. 排序（`level`）与重排成本

- `level` 只能通过 `channel/update` 逐条改；**没有批量重排接口**。
- 官方**没有定义**：数值大小与「靠前/靠后」的对应关系、相同 `level` 时的次序规则、分组与频道是否共用一个序空间、取值范围（T2）。
  - 观察到的示例值：`channel/list` 示例 `level: 100`、`channel/view` 示例 `level: 3`、`objects` 示例 `level: 1`、`channel-user` 示例 `level: 200`。
- **成本模型**：N 个频道重排 ⇒ N 次写请求 ⇒ ① 限流预算（§10）；② **N 个自己触发的 `updated_channel` 事件**（§8）。
- ⇒ 重排必须**只在真正有差异时**执行（幂等 reconcile，见 `03`），不要每次跑都无脑写一遍。

| 接口 | 方法 | 参数 | 说明 |

⇒ 「语音频道维护」（清空闲置语音频道、按需求把用户挪房）是**可行**的，但两道硬约束：目标必须是语音频道、用户必须已经在语音里。

### 7.2 机器人自己进语音/推流（`/doc/http/voice`，2024-08 上线）【已核实】

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/v3/voice/join` | POST | 加入语音频道，返回 RTP 推流地址/端口/`bitrate`/`audio_ssrc`/`audio_pt` |
| `/api/v3/voice/list` | GET | 机器人已加入的语音频道列表（`id/guild_id/parent_id/name`） |
| `/api/v3/voice/leave` | POST | 主动离开（**建议不再用时主动调，释放资源**） |
| `/api/v3/voice/keep-alive` | POST | 每 **45s** 调一次，避免端口资源被回收 |

## 8. 事件（系统消息）【已核实】

### 8.1 事件信封

```json
{
  "s": 0,
  "d": {
    "channel_type": "GROUP",
    "type": 255,
    "target_id": "6016389000000",
    "author_id": "1",
    "content": "[系统消息]",
    "extra": { "type": "added_channel", "body": { } },
    "msg_id": "…",
    "msg_timestamp": 1612776265417,
    "nonce": "",
    "verify_token": "…"
  },
  "sn": 21
}
```

| 字段 | 含义 |
| --- | --- |
| `s` | 信令：`0` = 事件消息 |
| `d.channel_type` | `GROUP` 组播 / `PERSON` 单播 / `BROADCAST` 广播 |
| `d.type` | `1` 文字 / `2` 图片 / `3` 视频 / `4` 文件 / `8` 音频 / `9` KMarkdown / `10` Card / **`255` 系统消息** |
| `d.target_id` | `channel_type=GROUP` 且 `type=255`（系统消息）时 = **服务器 `guild_id`**；普通频道消息 = `channel_id` |
| `d.author_id` | 发送者 id，**`1` 代表系统** |
| `d.extra.type` | 事件类型（下表） |
| `d.extra.body` | 事件数据 |
| `sn` | 该 session 的消息序号（顺序处理 + resume 用） |

### 8.2 频道相关事件（`/doc/event/channel`）

| `extra.type` | `body` 内容 |
| --- | --- |
| `added_channel` | **完整 Channel 对象**（含 `permission_overwrites` / `permission_users` / `permission_sync` / `topic` / `slow_mode` / `level`…） |
| `updated_channel` | **完整 Channel 对象**（改后的值） |
| `deleted_channel` | `{ id, deleted_at, type }` |
| `pinned_message` / `unpinned_message` | `{ channel_id, operator_id, msg_id, channel_type }` |
| `added_reaction` / `deleted_reaction` | `{ msg_id, user_id, channel_id, emoji, channel_type }` |
| `updated_message` / `deleted_message` | 消息体/`{ msg_id, channel_id, channel_type }` |

⚠️ **关键缺口**：`added_channel` / `updated_channel` 的 body **只有频道对象，没有操作人**（`pinned_message` 反而有 `operator_id`）⇒ **无法从事件判断「是我自己改的还是别人改的」**。防回环只能靠幂等与本地时间窗（见 `03`）。

### 8.3 其他相关事件族

| 页面 | 事件（`extra.type`） |
| --- | --- |
| `/doc/event/guild-role` | `added_role` / `updated_role` / `deleted_role`（body = Role 对象，含 `permissions` 位） |
| `/doc/event/guild` | `updated_guild` / `deleted_guild` / `added_block_list` / `deleted_block_list` / `added_emoji` / `removed_emoji` / `updated_emoji` |

**角色事件的存在很重要**：角色权限位变了（`updated_role`）可能让原本「看得见/发得了言」的频道失配 ⇒ 这是**权限漂移**的触发源之一（另外两个是 `updated_channel` 与人工后台改动）。

### 8.4 投递方式与信令

**WebSocket**（`/api/v3/gateway/index` 取 wss 地址）：

| 信令 | 方向 | 说明 |
| --- | --- | --- |
| 0 | s→c | 事件消息（带 `sn`） |
| 1 | s→c | HELLO（`{code, session_id}`；**6s 内必须收到**） |
| 2 | c→s | PING（**每 30s ±5s**，带当前最大 `sn`） |
| 3 | s→c | PONG（**6s 内没收到 = 心跳超时**） |
| 4 | c→s | RESUME（带最后处理成功的 `sn`） |
| 5 | s→c | RECONNECT（**要求清空本地 `sn` 与消息队列，重新获取 gateway**） |
| 6 | s→c | RESUME ACK |

- 握手失败码：`40100` 缺少参数 / `40101` 无效 token / `40102` token 验证失败 / `40103` token 过期。
- RECONNECT 码：`40106` resume 缺参数 / `40107` session 过期 / `40108` 无效或已不存在的 `sn`。
- 重连：先 2 次 PING（间隔 2、4），不成功再 2 次 resume（间隔 8、16），再回退到重新取 gateway（指数退避，最大 60s，无限重试）。
- **压缩**：`gateway/index?compress=1`（默认）时**服务端下发的都是 zlib(deflate) 压缩的 binary**；客户端上行**不要压缩**。不压缩就传 `compress=0`。
- **`sn` 处理铁律**：按 `sn` 顺序处理；乱序先入 buffer；已处理的 `sn` 直接丢弃；PING 要回传「已处理成功的最大 sn」，落后时服务端会重推。

**Webhook**（`/doc/webhook`）：与 WebSocket **互斥** —— 官方原文：「如果选择了 Webhook 模式，将不能再使用 Websocket 接收用户消息；同理设置了 Websocket 后，平台不会再向回调地址推送」。Webhook 的 `sn` 到 65535 后回到 1（WS 无上限、从 1 自增）。

**订阅机制（重要更正）**：`GET /api/v3/user/me` 的返回里**有 `intent` 字段**——官方原文标注为「**事件订阅掩码**，默认为 `-1` 接收所有」（示例里出现过 `255`）。⇒ **订阅机制是存在的**，但**文档没有说明各位的含义、也没有任何接口说明怎么改它** ⇒ 【未文档化】（T16）。
在拿到 T16 结论之前，实现仍应**自带事件过滤与丢弃逻辑**（不能假设只收自己关心的事件）；另外「机器人看不到的频道是否也推送事件」同样没说明（T1）。

- **消息配额（重要）**：按**开发者账号**维度，账号下所有机器人**单日合计 10,000 条**，**北京时间 12:00 重置**。计入配额的接口：`message/create`、`message/update`、`direct-message/create`、`direct-message/update`、`thread/create`、`thread/reply`。**请求失败不计**；**临时消息（`temp_target_id`）不计**；对「5 分钟内用户发到当前频道的消息」的**首次回复按大幅折扣**计（`reply_msg_id`）；**模板消息（计划中）不计配额**。
- ⇒ 频道维护里凡是「发公告/发频道导航」的动作都要按**每日 10,000 条**的账号级预算设计（多机器人共享同一账号额度）。
- 官方安全提示（原文大意）：**强烈建议过滤掉机器人自己发的消息再回应**，否则两个机器人可能循环自言自语导致发送量过大、**被封禁**。

## 10. 限流【已核实】

响应头：

```
X-Rate-Limit-Limit: 5        // 一段时间内允许的最大请求次数
X-Rate-Limit-Remaining: 0    // 一段时间内还剩下的请求数
X-Rate-Limit-Reset: 14       // 恢复到最大请求次数需要等待的时间
X-Rate-Limit-Bucket: user/info   // 请求数的 bucket
X-Rate-Limit-Global          // 触犯全局请求次数限制
```

- 超限 ⇒ **HTTP 429**，返回体格式与标准格式一致，**头依旧会传**。
- 官方警告：多次超速会被警告；**继续不改可能被禁用 bot**（引言页措辞更重：可能撤销 API 密钥并限制登录）。
- **各接口的桶容量与窗口未公开**（文档只给了示例值 5 / 14s，bucket 例子是 `user/info`）⇒ 实现必须**运行时读头自适应**，不能写死阈值（T9）。
- ★**实测（2026-10-09，本机器人）**：**按接口分桶**（`user/me`、`guild/view`、`channel/view`、`guild-role/list`、`guild/user-list` 各自一个 bucket），实测 **`Limit = 240`、`Remaining = 239`、`Reset = 0s`** ⇒ 读接口的实际额度比文档示例宽松得多；**写接口（asset/create、message/create、thread/create）的桶待单独实测**（T9 未做完）。

### 10.1 写操作的「调用量放大器」

「建一套频道」的真实请求量估算（受 §3.3 与 §4 约束）：

| 动作 | 请求数 |
| --- | --- |
| 建 1 个分组 | 1（create） |
| 建 1 个文字频道（含简介+慢速） | 1（create）+ 1（update） |
| 给该频道加 k 条角色权限覆写 | k（channel-role/create，且可能还要先 index 读现有） |
| 重排 n 个频道 | n（update） |
| **每次「对账」若不做差异判定** | 上面全部**重复一遍** |

⇒ 结论：**必须做「先读后写、无差异不写」的 reconcile**，并把写操作**串行化 + 自适应退避**（见 `03`）。

## 11. 能力缺口清单（官方没有的东西）

| 缺口 | 影响 | 绕行 |
| --- | --- | --- |
| **批量重排 / 批量创建 / 批量删除频道** | 一次重排 = N 次写 | 串行 + 退避；只在有差异时写 |
| **频道回收站 / 删除恢复** | 误删不可逆 | 删前 `channel/view` 快照归档 + dry-run + 二次确认 |
| **按名字查频道** | 无法直接「按名找 id」 | `list`/`guild/view` 全量拉回本地建索引 |
| **`updated_channel` 事件的操作人** | 无法判断改动来源 | 幂等 reconcile + 本地时间窗（`03`） |
| **最终生效权限查询** | 无法直接问「机器人能不能在这发言」 | 自算：角色位 ⊕ 频道覆写（§4.4） |
| **文档化的错误码表** | 错误分类困难 | 运行时采集 `code`+`message` 自建字典（§1.1） |
| **频道数量上限 / 名称长度 / 分组嵌套规则 / 分组删除是否级联** | 边界行为未知 | 全部进 `02-待实测清单.md` |
| **订阅/意图机制（按事件类型筛选）** | 全量事件都推来 | 客户端过滤 + 丢弃 |

### 帖子频道（`type=4`）怎么发布【已核实 + 实测存在】

帖子频道是「允许用户在内产生帖子内容」的频道类型；术语：**主楼**（发帖内容）/ **回复**（一级回复）/ **楼中楼**（回复的回复）；**分区（Category）** 可选，不选即「综合」。

| 接口 | 方法 | 关键参数 | 说明 |
| --- | --- | --- | --- |
| `/api/v3/thread/create` | POST | `channel_id`、`guild_id`、`title`、`content`（**卡片消息内容**）、`category_id?`、`cover?` | 发帖（主楼）。返回 `post_id` / `medias` / `preview_content` + Thread 对象 |
| `/api/v3/thread/reply` | POST | `channel_id`、`thread_id`、`content`（**文本**）、`reply_id?` | 评论/回复主楼或某楼 |
| `/api/v3/thread/view` | GET | `channel_id`、`thread_id` | 帖子详情（含 `status`） |
| `/api/v3/thread/list` | GET | `channel_id`、`category_id?`、`sort`(1 最新回复/2 最新创建)、`time` 翻页 | 帖子列表 —— ★**2026-10-10 实测**：`?channel_id=…&sort=2` ⇒ **200**、桶 `thread/list`、返回 **`{items:[…]}`**、**一次拿全**（10 条一条不少、未用 `time` 翻页）；条目键见 `CLAUDE.md` §二·补 |
| `/api/v3/thread/post` | GET | `channel_id`、`thread_id`、`order`、`page` | 回复列表 |
| `/api/v3/thread/delete` | POST | `channel_id`、`thread_id` / `post_id` | 删帖 / 删楼 |
| `/api/v3/category/list` | GET | `channel_id` | 帖子分区列表 |

- ★**`thread/create` 与 `thread/reply` 都计入每日 10,000 条消息配额**（与 `message/create` 同一份账）。
- ★帖子有审核状态 `status`：`1` 审核中 / `2` 审核通过 / `3` 编辑审核中 ⇒ 发完必须**回读 `thread/view` 确认 `status=2`**，否则频道里看不到（T17）。
- ★主楼 `content` 用的是**卡片消息格式**（含 `file` 模块能否用在主楼里 = 未验证，T17）。
