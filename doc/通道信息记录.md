## 0. 一句话结论

- **本客户端的「战斗信息」只有聊天文字（CHAT_MSG_*）这一条路**：没有任何 COMBAT_LOG 类 API、没有仇恨/威胁 API、没有敌人枚举 API、读不回 ChatFrame2。
- 事件名**官方索引里没有**（85 个分类里没有 Events）⇒ 只能真机枚举。**已用两条独立路径交叉验证**（见 §2）。
- **聊天窗口消息组这条路在本客户端不可用**（战斗文字不挂在任何消息组上，见 §4）。

## 4. ❌ 不可用 / 拿不到（别再花时间）

| 项 | 实测结论 |
|---|---|
| **聊天窗口消息组**（`GetChatWindowMessages`） | `GetChatWindowMessages(1)` 只有 1 组且**不含 COMBAT**；`GetChatWindowMessages(2)` 只有 1 组 = `COMBAT_ERROR` ⇒ **战斗文字根本不挂在消息组上**，`CHAT_MSG_ + 组名` 这条推导在本客户端**不成立**（Toolbox 那条「通知组」是 Channel 类，属另一套） |
| **读回 ChatFrame2** | `ScrollingMessageFrame` 官方共 **16 条方法**：`AddMessage` / `AtBottom` / `AtTop` / `ScrollDown|Up|ToBottom|ToTop` / `SetFading` / `SetFont` / `SetFontObject` / `SetJustifyH|V` / `SetMaxLines` / `SetTimeVisible` / `UpdateColorByID` ⇒ **没有 `GetMessageText` / `GetNumMessages`**，内容读不回来 |
| **`frame.AddMessage` 包装** | 实测**写进去不生效**（0/8，1.73.12 定案）⇒ 只能挂 `ChatFrame_OnEvent` |
| **COMBAT_LOG 类 API** | `COMBAT_LOG_EVENT_UNFILTERED` / `GetNumCombatLogMessages` / `CombatLogGetCurrentEventInfo` **0 条**（那是 2.4+ 的东西） |
| **`LoggingCombat`** | 官方有（`[ChatWindow]`），但 `Saved` 下**没有 Logs 目录**、全盘无 `*CombatLog*`；且**插件没有文件读取 API** ⇒ 只对人有用，不能当数据源 |
| **`UELog` / `RLog`** | 已实测弃用（`Core.lua:108-110`：UELog 调用成功但什么都不落盘；RLog 仅 debug 构建） |
| **仇恨 / 威胁** | 官方索引 0 条 |
| **敌人 / 附近单位枚举** | 官方索引 0 条 ⇒ 只能 `TargetNearestEnemy` 循环切目标（本项目已降级为手工命令 `/eh go melee 周围 切目标`） |
| **`UnitCastingInfo`** | 本项目已定案：没有 |

## 5. ✅ 唯一可靠的抓法：`ChatFrame_OnEvent` 截获

- 第一轮实测：**经过 55 条 ｜ 取不到文本 0 条**；事件名直接从截获里读出来（`CHAT_MSG_… ｜ 正文`）。
- 取参兼容三形态（Toolbox 的 `tbCeArgs` 教训）：
  1. `ChatFrame_OnEvent(event)` + 全局 `arg1..arg9`（1.12 老写法）
  2. `ChatFrame_OnEvent(event, 文本, 发送者, …)`
  3. `ChatFrame_OnEvent(self, event, 文本, 发送者, …)`
  ⇒ 判据 = 把 varargs 全收进表，**挑以 `CHAT_MSG` 开头的那个当事件名**，其余里第一个字符串当正文。
- 实测噪声：`nil ｜ EXECUTE_CHAT_LINE`（客户端内部占位调用，忽略即可）。
- ★`ChatFrame2` **就是战斗记录页**（`tools/DragFrames.lua:136-137`：综合 = ChatFrame1 / 战斗记录 = ChatFrame2，同一窗口两页）；它由 FrameXML **懒建** ⇒ 没点开过可能不存在。

## 6. 文案模板（真机原文，解析判据直接照这些写）

```
【怪近战打我】    <怪>击中你造成N点伤害。            <怪>击中你造成N点伤害。（1点被格挡）
【怪未命中】      <怪>发起了攻击。你招架住了。        <怪>发起了攻击。你闪躲开了。
【我平砍命中】    你击中<怪>造成N点伤害。            你击中<怪>造成N点伤害。(偏斜)
【我未命中】      你没有击中<怪>。
【我方 DoT】      你的撕裂使<怪>受到了5点物理伤害。
【击杀（两条）】  你杀死了<怪>！                     <怪>死亡了。
【怪施法/增益】   <怪>开始施展急速冲锋。              <怪>获得了急速冲锋的效果。
【光环消失】      急速冲锋效果从<怪>身上消失。
【别人治疗我】    <玩家>的次级治疗术为你恢复了50点生命值。
【敌对玩家施法】  <玩家>开始施放暗言术：痛。
```

★ 解析注意：
1. 名字一律**从正文认**（`arg2` 是 nil）；多字节判断按 **UTF-8 首字节**（CJK 字 E4~E9；标点 E2/E3/EF）—— 按 GBK 的 `A1/A3` 判会漏（实测踩过：`你闪避了。` 被认成攻击者名叫「。」）。
2. `X的Y击中你…` 要**归一到「的」之前**（否则同一只怪按两个名字各记一笔 ⇒ 围攻数虚高）。
3. `（1点被格挡）` / `(偏斜)` 这类后缀不影响解析（名字在动词之前）。
4. 击杀**必须去重**（同一只怪两条文案，1 秒内同名只计一次）。
