**读法**
- 「伤害加成 / 护甲加成 / 生命加成」= 相对标准宠物的**基础系数修正**（猫科 +10% 伤害 = 输出取向；乌龟/螃蟹 +13% 护甲、熊 +8% 生命 = 坦克取向；猪/乌龟 −10% 伤害 = 输出最差）。
- 「食物」列 = 该家族**可吃的食物类**（决定喂食能喂什么，与 `GetPetFoodTypes` 同族信息）。
- 三个技能列 = 该家族**天生会**的技能（伤害 / 加速=位移 / 特殊），是「抓它能不能学到某个技能」的家族级真值。
- 图片第 17 行特殊技能写作 **「狂怒之嚎」**，而现有 `PetData.skills` 里叫 **「嚎叫」**（狼系来源：座狼/血斧座狼/魔爪狼…）⇒ 疑似同技能两名，**待真机核对**（见 §四）。
- 现有图标清单里 17 个家族的家族图标**全部存在**（`Ability_Hunter_Pet_{Cat,Raptor,Bat,Owl,Spider,WindSerpent,Gorilla,Crab,Scorpid,Bear,Boar,Turtle,Vulture,Crocolisk,Hyena,TallStrider,Wolf}_TEX`），`raptor` / `hyena` 缺的只是**数据条目**，不是素材。

## 二、与现有抓宠帮手（`PetData.lua` + `PetHelper.lua`）的关系

现有结构（可直接扩展，不用新建文件）：

| 现有件 | 内容 | 本图补充什么 |
| :-- | :-- | :-- |
| `EVAL_PET_DB.skills` | 21 条技能（含图标/集中/射程/CD/简介） | 不变（技能列引用的名字全部能在其中找到 ✓） |
| `EVAL_PET_DB.ranks[技能]` | 技能 → 等级 → **驯服来源野兽**（280 条，带 `fam`） | 提供「家族 → 技能」的**反向真值**，可用于校验 `fam` |
| `EVAL_PET_DB.families[id]` | 16 条（label + 图标），含 `other` | **要扩成 17 条家族 + 三加成 + 食物 + 三技能列**（`bird` 改名「食腐鸟」、新增 `raptor`/`hyena`） |
| `PetHelper.lua` | Tab6：技能检索列表 → 技能详情（等级 + 需求 + 驯服来源宠物行，行内已显示家族图标/名） | 新增「家族」视图（列表 → 家族详情），并用家族图标当入口 |

**关键发现：`fam` 标注现状不可信。** 用图片的「家族 → 技能」当约束表反向校验 280 条来源：

- **64 条冲突（23%）**，按技能分：撕咬 21 · 畏缩 12 · 闪电吐息 8 · 突进 6 · 嚎叫 6 · 爪击 4 · 俯冲 3 · 蝎毒 2 · 冲锋 1 · 尖啸 1。
- **典型错标模式（可由约束表直接定案）**：
  - 「狼」字带偏 → **狼蛛 / 巨型狼蛛 / 平原狼蛛 / 巨型平原狼蛛 / 死亡狼蛛** 被标成 `wolf`（应为 `spider`）。
  - **土狼系**（骨爪土狼 / 玛格拉姆骨爪土狼 / 疱爪土狼 / 疯狂的疱爪土狼 / 饥饿的疱爪土狼）被标成 `wolf`（应为新的 `hyena`）。
  - **雷鹰雏鸟 / 雷鹰破云者 / 大型雷鹰 / 山谷尖啸者 / 游荡的山谷尖啸者** 标成 `bird`，但它们教「闪电吐息」⇒ 只可能是 `windserpent`。
  - **异种爬行者**（教蝎毒）标成 `spider` ⇒ 应为 `scorpid`；**恐怖撕裂者**（教尖啸）标成 `spider` ⇒ 应为食腐鸟/蝙蝠族。
  - **掠夺者科拉克** 标成 `scorpid`，但它教「撕咬+爪击」⇒ 按图只能是 `bird`（食腐鸟）。
  - **嚎叫的 6 个来源**（山狗首领 / 巨型黑色破坏者 / 幽爪前锋 / 老峭壁山狗 / 长牙奔跑者 / 长牙嚎叫者）全是 `other` ⇒ 按图「嚎叫只有狼」必为 `wolf`。
- **真冲突（图与现有数据二选一错，需定案）**：
  - `畏缩` 12 条：图里只把畏缩放**猫科**，但现有数据里陆行鸟/蝙蝠/枭/熊也教畏缩 ⇒ 图可能只列「天生技能」，畏缩在训练师处各族都能学。
  - `冬泉鸣枭`（标 `owl`）教**撕咬 8** —— 图里猫头鹰只有爪击。
  - `尘泥钳嘴鳄鱼`（标 `crocolisk`）教**爪击 4/5** —— 图里鳄鱼只有撕咬。
- `other` 桶仍有 **36 只唯一（44 条）** 未归类，其中光凭「有撕咬」定不了家族（14 个家族都会撕咬）。

> **结论**：家族属性一旦上图，用户会**看着家族三围选宠**（如「抓猫科玩输出」）——`fam` 标错会直接误导决策（「狼蛛」显示成狼＝护甲 +5% 是错的）。所以「家族属性」与「`fam` 标注修正」必须**同一轮做**，或至少把 `fam` 修正做成**可执行闸门**（固定现状冲突数，只许减不许增）。

## 三、整合方案（三层）

### L0 数据层 —— `PetData.lua`（单一真值，不新开真值表）
把 `families[id]` 从「label + icon」扩成完整家族卡：

```lua
cat = { label = "猫科", icon = ".../Ability_Hunter_Pet_Cat_TEX",
        dmg = 10, armor = 0, hp = -2,
        foods = { "鱼", "肉" },
        sk = { dmg = {"撕咬","爪击"}, spd = {"突进"}, sp = {"潜伏","畏缩"} },
        cname = { zhCN = "猫科", enUS = "Cat" } },   -- 给 UnitCreatureFamily 对账用
```

### L1 界面层 —— `PetHelper.lua`（Tab6 加第三视图「家族」，不新开 Tab）
- 列表视图顶行加 `[家族]` 切换；家族列表 17 行 = 图标 + 名 + `伤+10% 甲— 命−2%` + 食物，复用现有 **15 行池 + 逐行滚轮**范式（内容高度、计数器、`EVAL_WHEEL_DIR` 全照现有）。

- 现有技能详情里的**宠物行家族图标/名可点** → 直接开该家族详情（最小改动、最有用的入口）。
