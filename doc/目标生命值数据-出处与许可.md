# 目标生命值数据（本服生物生命值库 / 名字表）—— 出处与许可

> 口径与 `doc/地图层数据-出处与许可.md`、`doc/物品价数据-出处与许可.md` 同一把尺子：
> **随插件走的是数据文件，运行期零第三方依赖**；出处、许可、生成方式都写在这里，生成物本身绝不手改。

## 1. 随插件的两个文件

| 文件 | 体积 | 内容 |
| --- | --- | --- |
| `UnitVitalsData.lua` | ~437 KB | `EVAL_UNIT_VITALS`：10,369 条生物模板（`class / rank / levelMin / levelMax / healthMultiplier / manaMultiplier`）+ `classLevel[class][level] = {hp, mana}`（class 1/2/8 × 等级 1~63，共 189 条）+ `rankHpRate`（本批全 1.0）+ 版本记号 `revision` / `migration` / `patch` |
| `UnitNamesData.lua` | ~1.13 MB | `EVAL_UNIT_NAMES_EN`（恒载入，兼回退表）+ `EVAL_UNIT_NAMES_ZH` / `EVAL_UNIT_NAMES_RU`（按客户端 `GetLocale()` 载入）：生物名 → 生物 id |

## 2. 出处

- **来源快照**：本机 `Interface\AddOns.Disabled\unrealUI`（版本 `0.10.2`，**MIT**）的
  `Database\unit_vitals.lua` 与 `Database\unit_names.lua` / `unit_names_zhCN.lua` / `unit_names_ruRU.lua`。
- **那份数据本身**：本服（EmberVeil / VMaNGOS 血统）世界数据的快照 —— 表内自带 `revision = 6958f2666be3feb7b5584f3a49cb36e5acf74172`、
  `migration = 20260822042038`、`patch = 10` 三个记号，原样保留。
- **本插件的改动只有两处**（表体**逐字节保留**）：
  1. 挂点从 `U.unitVitals` / `U.unitNames` 改成 `EVAL_UNIT_VITALS` / `EVAL_UNIT_NAMES_*`；
  2. 名字表的 locale 闸门从「三份**互斥**」改成「**enUS 恒载入 + 客户端 locale 那一份**」
     （本服 zhCN 数据里有 128 个 id 没有中文名，客户端会直接显示英文名 ⇒ 只带 zhCN 表就查不到）。

## 3. 生成方式（**生成物，绝不手改**）

```
node tmp/gen_unitdata.js        # 从上面那份快照重生成两个文件（改数据请重跑，别手改）
node tmp/verify_unitdata.js     # fengari 真载入 + 规模核对 + 算式自证
node tmp/vitals_conflict_check.js   # (名字,等级) → 最大生命值 唯一性
node tmp/vitals_union_check.js      # 三语并集覆盖率与冲突
```

## 5. 许可与使用边界

- unrealUI 本体 = **MIT**（其 `LICENSE` 随其安装目录）；本插件**只取数据表**，不取它的任何代码。
- 数据内容 = 本服世界数据快照。本项目对第三方数据的既定纪律：
  **随插件自带、运行期不读别的插件/不联网**；若上游数据更新，按 §3 重跑生成器即可（版本记号会跟着变）。
- **已知不覆盖**：`UnitLevel` 返 **-1** 的骷髅/世界首领（官方 wiki 原文：高出玩家 10 级以上的敌对单位与世界首领）；
  本服 zhCN 数据里没有名字的那 128 个 id（并集后剩 2 个）；非中 / 英 / 俄语客户端（名字表没有那一份）。
  这三种情况消费方（`tools/TargetHealth.lua`）**一律退回百分比**，绝不编数字。
