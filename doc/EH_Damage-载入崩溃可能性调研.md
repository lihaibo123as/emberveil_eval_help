## 1. 「载入」指哪一步 —— 三种含义指向完全不同的嫌疑

| 用户说的「载入」 | 那一刻实际在跑什么 | 首要嫌疑 |
| :-- | :-- | :-- |
| **选人界面 / 客户端读插件那一刻** | 只有三个 `.lua` 的**文件顶层**：建表 + `_G["EH_DMG"]=D` + `CreateFrame("Frame")` + `RegisterEvent("VARIABLES_LOADED")` + `SlashCmdList` 注册（有 `type` 守卫） | 这一层几乎无嫌疑（下面 §2 逐条列了，全是纯 Lua 表构造） |
| **进世界那一拍** | `VARIABLES_LOADED` 处理器：`cfgEnsure()` → **`D.iconScan()`** → `eventSync()` → `beatSync()` → `say()` | **§3.1 `iconScan`**（唯一批量原生调用）、§3.2 载入抛错 |
| **进游戏后第一次战斗** | 第一次 `addText` → `faLayout` → `SetTexture(Interface\AddOns\EH_Damage\media\fontdigits_*.tga)`（`fontAtlas` 默认 **true**） | **§3.3 图集贴图解码**（这不是「载入」，但用户很可能这么描述） |

★★ **已确认（用户 2026-10-10 追加）**：「载入」= **进世界那一拍就崩/秒退**；**报障来自其他用户**（不是本机）⇒ 首要嫌疑 = §3.1（`iconScan`，进世界那一拍唯一的批量原生调用）与 §3.2（载入期抛错）；
用户同时问「**是否和用户存储有关系**」⇒ 专项分析见 **§8**。

## 2. 载入期到底跑了什么（逐条锚点，全量）

**文件顶层（`EH_Damage.lua`，2356 行；`EH_Damage.lua:35` 起）** —— 全部是表构造与常量，**没有任何客户端写动作**：
`_G["EH_DMG"] = D`（35）· `DIRS/CURVE/DEF/ITEMS/COLOR/KIND_ITEM`（60~432）· `D.INOFF_MIN…`、`D.FAS_ORD/FAS_ZH/FAS_SETS`（142~181）·
`local boot = CreateFrame("Frame")` + `boot:RegisterEvent("VARIABLES_LOADED")`（2298~2299）·
`SlashCmdList["EHDAMAGE"]` + `rawset(_G,"SLASH_EHDAMAGE1/2")`（2289~2293，`type(SlashCmdList)=="table"` 守卫）。
★ **载入期不建槽池帧、不建配置面板**：槽池（`POOL_MAX = 40` 个 2048×512 的帧）走 `slotAcquire` **按需建**（758~789）；
配置面板帧 `EH_DMG_UI` 只在 `/edmg ui` 里建（`uiBuild`，1759 起）。

**`VARIABLES_LOADED` 那一拍（2300~2306）**：
1. `cfgEnsure()`（185~249）：只读写**自己的**存档根 `EH_DAMAGE_CFG`（`rawget(_G,…)`），只补 nil 键 + 两条「只升级旧默认确切值」的一次性迁移；**没有破坏性迁移**。
2. **`D.iconScan()`（291~326）** ← 唯一「载入期批量原生调用」，见 §3.1。
3. `eventSync()`（1448~1476）：`CreateFrame("Frame","EH_DMG_EVENT")` + 逐个 `pcall(RegisterEvent)`（约 30 个事件名）。
4. `beatSync()`（1110~1122）：`CreateFrame("Frame","EH_DMG_BEAT", WorldFrame or UIParent)`，按 `c.master` 挂/摘 `OnUpdate`。
5. `say(...)`（256~260）：`pcall(DEFAULT_CHAT_FRAME.AddMessage, …)`。

**结论**：载入期唯一「有分量」的动作就是第 2 步。

## 3. 逐条可能性

### 3.1 ⚠️ 主嫌：`iconScan` 的越界扫描（唯一「载入那一刻就在打原生 API」的地方）

- **代码**（`EH_Damage.lua:291~326`）：`for i = 1, 900` 调 `GetSpellName(i,"spell")` + `GetSpellTexture(i,"spell")`（**先 name，后 tex**）⇒ 再加 `GetPetActionInfo(1..10)` ⇒ 再加 `GetSpellName/GetSpellTexture(i,"pet")` i=1..30。**最坏 ≈1870 次客户端调用**，全在 `pcall` 里。
- **现守卫**：`type(GetSpellName) == "function"` 等两道 + 每次调用 `pcall` ⇒ **Lua 侧错误全兜住**；循环靠 `if not okN or not name then break end` 提前结束（本客户端越界返回 nil，所以实际约 2×法术书条数）。
- **为什么它排第一**：`pcall` **只能兜 Lua 异常，兜不住原生访问违规**。若**另一个客户端/版本**的 C 侧对越界下标不做检查（本客户端是 UE 移植层），`GetSpellName(901, …)` 这类调用就是**载入期直接崩**。而这是全插件唯一「载入期拿越界下标去打原生 API」的地方。
- **判据（可复算）**：本机是把 900 这个**写死上界**当探针用的（同类写法在 `GetPetActionInfo` 也用满了 10）。⇒ 只要那个环境的崩溃点在 `VARIABLES_LOADED` 那一拍、且栈里出现 spellbook 相关符号，就是它。
- **修法方向（等你确认，暂不动手）** —— ★**已按「不影响功能吗?」逐条核过，只有 ① 可以做成零功能变化**：
  ① **上界改成「现读法术书条数」**（**保留「遇 nil 就 break」原语义；拿不到 API / 读不出 ⇒ 退回今天的 900**）：
  `GetNumSpellTabs()` + 逐 tab `GetSpellTabInfo(i)` 取 `offset + numSpells` 的**最大值**再留一点余量。
  ★ **权威出处 = 客户端自带 FrameXML**（`tmp/mpq_out/Interface/FrameXML/SpellBookFrame.lua:24/36`：
  `local name, texture, offset, numSpells = GetSpellTabInfo(i)`；`Blizzard_MacroUI.lua:248~249` 同款写法）
  ⇒ 返回顺序可核、`GetNumSpellTabs` 确实存在（本机 `api_action.html` 也命中）⇒ 这条修法成立。
  ⇒ **为什么它是零功能变化**：今天本来就是「遇到返回 nil 的那一格就停」，而真实条数 ≤900，
  所以**图标集一字不差**，只是把「900 次里的越界部分」换成「真实条数」。
  ② **撤回**：`name == ""` 也算停 —— **空串现在是「跳过这一格、继续扫」**，改成停止会在遇到中间空串时
  **丢掉后面所有技能图标**（真机行为风险）⇒ **不许这么改**。
  ③ **撤回**（列为可选、不建议）：把 `iconScan` 挪到「首次真的需要图标」——**有可观察差异**
  （载入期不再扫 ⇒ 首战前 `/edmg 状态` 的「模拟技能池」可能空、首战那一刻才有图标）。
- **注意**：这一条**不能靠离线判**（本客户端不崩就是最好证据，别的环境崩不崩只有那边能答）。

### 3.2 ⚠️ 次嫌：`FontDigitsExtra.lua` 的无守卫跨文件硬索引（载入期可抛错）

- **代码**（`FontDigitsExtra.lua:7~35`）：`local D = rawget(_G,"EVAL_EDMG_FONTDIGITS")`（有 `type(D)=="table"` 守卫）——但紧接着**硬索引 `D.tiers[1].st[...]` … `D.tiers[6].st[...]`（1/2/3/4/5/6 全写死，共 24 条）**。
- **风险**：只要 `tiers` 少于 6 项（**旧版 FileDigits / 半装 / 被别的同名全局顶掉**）⇒ `attempt to index field 'st' (a nil value)`，**载入期就报**。本客户端会显示红字（不一定崩进程），但如果**那个环境把载入期 Lua 错误当致命**，用户看到的就是「一载入就崩」。
- **`EH_Damage.lua` 侧是安全的**：`faEnsure`（448~478）对表形态逐项 `type` 守卫（`file` 必须 string、`h` 必须 tonumber、`cw/cx/st` 非表就当 nil）——**同一份数据，两个消费者，一个防了、一个没防**。
- **现实触发场景**：「其它环境」最常见的成因 = **只覆盖了一部分文件**（只解压 `.lua`、先装旧版再覆盖新版的几个文件）⇒ `FontDigits.lua` 与 `FontDigitsExtra.lua` 版本不配套。
- **修法方向（等你确认）**：把 6 处硬索引收进 `for i = 1, table.getn(D.tiers) do`，**有第 i 档就写、没有就跳过并如实记一行**（绝不新建假档）。

### 3.3 ⚠️ 不是「载入」而是「首战」：图集贴图在别的客户端/版本上解码失败

- **素材体检（本次实测，54/54 全绿）**：类型 `type=10`（RLE）· `32bit` · 逐张**全量解码像素数精确**（`W×H` 与 RLE 游程累计**完全相等**）· **无截断、尾部余 0 字节**；最大 `1051×84`（`fontdigits_soft_6`），54 张解码总量 **5.60 MB**；`FontDigits.lua`/`FontDigitsExtra.lua` 里声明的 **54 条 `W` 与文件头逐条一致**。
- **在案事实（本项目）**：本客户端**只认 BLP/TGA**；**BLP2 的 JPEG 分支会直接崩客户端**（`1.75.62` 实测：`Trying to resize TArray to an invalid size of 4278180095`）——**我们的素材是 TGA，不走那一支**；散装 `.tga`（含 NPOT）在本客户端**已长期真机验证**（`0.2.29` 起就在用）。
- **剩下判不出的部分**：**另一个客户端/版本**认不认「type-10 RLE + 32bit + 非 2 的幂宽（1051/1033/1024…）」——离线**没有**判据（本客户端没有文件读取 API，只能真机 `SetTexture` 看屏）。
- **触发时机**：**默认 `fontAtlas = true`** ⇒ 进游戏后**第一次战斗数字**就会 `SetTexture` 到图集 ⇒ 用户很容易把它描述成「装了之后一进游戏就崩」。
- **现场判据（两条只读，都在现命令里）**：`/edmg 状态`（看 `图集=开/关`）· `/edmg 图集`（逐档探贴图 + **负对照** ⇒ 判「探针可信度」）。
  **最省事的 A/B**：`/edmg 图集关` → 打一场怪；不崩 = 贴图这一支；仍崩 = 排除贴图。

### 3.4 ℹ️ 环境差异项（不会崩，会静默缺图）：目录名与路径写死

- 54 条贴图路径 + `FontDigitsExtra.lua` 全部写死 **`Interface\AddOns\EH_Damage\media\…`** ⇒ **目录名必须逐字是 `EH_Damage`**。
- 别的环境若把文件夹改名（解压成 `EH_Damage-master`、或手动塞进 `EvalHelp\addons\EH_Damage` 而不放同级）⇒ 贴图 404。
- **404 会崩吗**？本客户端在案：**不存在的文件也可能报出非 0 尺寸、不崩**（`1.75.53b` 探针结论）⇒ 大概率是「画不出来/回落文字行」；**别的环境未知**，所以列在「环境差异项」而不是「已排除」。

### 3.5 ℹ️ 环境差异项：文件不齐 / 版本不配套（「其它环境」最常见的成因）

- **发布包该有什么（唯一口径 = `tmp/pack_subaddons.ps1`）**：`EH_Damage.toc` 列的运行时文件（`FontDigits.lua` → `FontDigitsExtra.lua` → `EH_Damage.lua`）+ `media\`（54 张 TGA）+ `README.md` + `CHANGELOG.md` = **58 个文件**（本机游戏目录 `..\EH_Damage` 实测 **58 个 / 1,881,363 字节**，逐项对得上）。
- **不进包**：`CLAUDE.md`（开发记忆）· `fonts\`（上游 TTF/成品位图）· `preview\`（截图）。
- **本机对齐判据**：`EH_Damage.lua` 的 `local BUILD = "0.2.46"` == `EH_Damage.toc` 的 `## Version: 0.2.46`（只读口 = `tmp/ehdmg_ver_check.js`）。
- ★ **目前没有「文件齐全」的闸门**（只有版本一致那一条）⇒ 半装环境查不出来。这是这次调研**新发现的一个判据缺口**。

## 4. 本机崩溃画像（为什么「其它环境崩」这个说法必须拆开）

- 崩溃转储 **65 个**（`%LOCALAPPDATA%\Azeroth\Saved\Crashes`）。按 `ErrorMessage` 归类：
  - 绝大多数 = `Unhandled Exception: EXCEPTION_ACCESS_VIOLATION`（读写**随机地址**，如 `0x00007fe900000010` / `0x000001c200000007`）。
  - 一批 = `LowLevelFatalError … MallocBinned3.cpp line 337  FMallocBinned3 Attempt to free an unrecognized small block …`（**堆损坏**）；同族 `MallocBinned2 Attempt to realloc … canary == 0x45 != 0xe3`。
  - 2 次 = `Crashing due to uobject leaks (world leaks)`（世界泄漏，与切地图/副本有关，不是插件侧的 Lua 能造成的）。
  - 1 次 = `Trying to resize TArray to an invalid size of 4278180095` + 转储里 `…/media/TexTest/LM_JPEGA.blp` = **当年那次 BLP2-JPEG 实测事故**（`1.75.62`）。
- **与 EH_Damage 的关系（全库字符串检索，ASCII + UTF-16）**：
  - `EH_Damage` / `fontdigits` / `EH_DAMAGE_CFG` / `EVAL_EDMG` ⇒ **0 命中**（65 个转储、一个都没有）。
  - **唯一 1 处**：`UECC-Windows-81A3460A…_0002`（2026-10-07 16:54，`EXCEPTION_ACCESS_VIOLATION 0x00007fe8b3d0f840`）里出现 **`EH_DMG_UI`**（= 配置面板的具名帧）。
    `EH_DMG_UI` 只在 `uiBuild`（`/edmg ui` 打开面板）时才建 ⇒ 能证明「那一刻插件是开着的、面板建过」，**不能证明因果**（堆里的一条字符串）。
  - 转储里出现过的**插件目录**只有 `EvalHelp`、`OneBag`、`unrealQuest`、`Blizzard_CombatText`（都是别的东西）。
- **⇒ 本机证据不支持「EH_Damage 载入必崩」，也不支持「图集贴图崩」**；它支持「这个客户端本身会随机崩（堆损坏/随机 AV）」。所以报障要先分清**确定复现（装了就崩）**与**随机崩**。

## 5. 一击定案需要什么（给「那个环境」的最小清单）

1. **崩溃 XML 的 `ErrorMessage` 一行**（`%LOCALAPPDATA%\Azeroth\Saved\Crashes\<最新>\CrashContext.runtime-xml`）—— 有这一行就能立刻分档（AV / 堆损坏 / 贴图解码 / 别的）。
2. **客户端构建信息**（同一 XML 里的 `GameName`/构建日期，或 exe 版本）—— 判「是不是同一个客户端版本」。
3. **A/B（最省事的两个开关，都不用改代码）**：
   - 勾掉子插件（或 `/edmg 关`）→ 还崩吗？**仍崩 = 与 EH_Damage 无关**。
   - 只 `/edmg 图集关` → 打一场怪：不崩 = §3.3 贴图支；仍崩 = 排除贴图，转 §3.1/§3.2。
4. **现场两条只读命令**：`/edmg 状态`（总开关/图集/槽数）· `/edmg 图集`（逐档探贴图 + 负对照 + 探针可信度）—— 都只读、不写盘。
5. **目录核对**：`Interface\AddOns\EH_Damage\` 是否 **58 个文件**（4 个运行时文件 + 54 张 `media\*.tga`），且目录名逐字 `EH_Damage`；`EH_Damage.lua` 的 `BUILD` 与 `.toc` 的 `## Version` 相同。

## 6. 若要改（**等你确认，本次一个字节都没改**）

★ **先纠正本文两处「写过头」的建议**（用户追问「不影响功能吧?」后逐条核代码发现）：
① 原写「上界收紧 + **`""` 也算停**」—— **`""` 不能在扫描中当停止条件**：它现在是「跳过这一格、继续扫」，一旦改成停止，
遇到任何中间空串就会**丢掉后面所有技能图标**（真机行为风险）⇒ **撤回这一半**；
② 原写「类型归一 + **夹取范围**」—— **夹取会改功能**：`posX/posY` 的拖拽写入口（`EH_Damage.lua:1680~1681`）是
`math.floor(D.drag.bx + (cx - D.drag.sx) + 0.5)` **没有夹取** ⇒ 用户把锚点拖到 ±600 以外是**合法状态**，
载入期夹取会把它拉回来 ⇒ **撤回「夹取」**，只保留「类型归一」。

## 8. 追加：用户存储面专项（用户 2026-10-10：「不是我和机子，是其他用户。是否和用户存储有关系?」）

### 8.1 先答结论（两层）

**第一层：本插件自己「写不坏」存档 —— 四条已在案的排除项**

| 排除项 | 证据（可复算） |
| :-- | :-- |
| ✅ 不触发本客户端那个「一行多名字」存档雷（`A B C = nil` ⇒ 每次登录弹红框） | git **全历史 10 个提交逐条核对**：`## SavedVariables: EH_DAMAGE_CFG` **十个版本全是单名** |
| ✅ 存档不会「越来越大」 | `ring` **首版（0.2.10）就有 `RING_MAX=80`**；本机实测存档里 `ring` 恰好 **1..80 连续 80 条**（无洞），`capture` 默认 false |
| ✅ 存档体量极小 | 本机三份实测 **3,024 / 5,009 / 9,039 B**（只有 3 个账号有这个文件）⇒ 不存在「存档太大读不动」 |
| ✅ 只碰自己的存档根 | 载入期只 `rawget(_G,"EH_DAMAGE_CFG")`；不读写宿主 `EVAL_HELP_CONFIG` / 别人的根（宿主契约②） |

**第二层：但「存储」仍然能解释「只有某些用户、进世界那一拍就崩」—— 三条机制，第 1 条最像**

| 机制 | 怎么发生 | 在案的形态 | 一步判据 |
| :-- | :-- | :-- | :-- |
| **存-1 存档文件损坏/截断**（最像） | 本客户端 SavedVariables **只在 `/reload`/退出时写盘**；写盘那一刻崩/被踢/被杀进程（本机 65 个转储证明「随机崩」是现实风险）⇒ **文件写一半** | 下次进世界时客户端 loadstring 这个文件 ⇒ 语法错；本客户端在案形态 = **每次登录弹一次红框**（多名字雷那次实测 `'=' expected near 'B'`）；**别的环境/版本可能更严厉** | 游戏关掉 → 把 `Saved\Account\<账号>\SavedVariables\EH_Damage.lua` **改名**（加 `.bak`）→ 再进游戏：**不崩 = 存储面实锤** |
| **存-2 写不进去** | 磁盘满 / 目录只读（装在 Program Files 无管理员）/ 杀软隔离 / 云盘同步锁 | 通常是「设置存不住」；**写到一半 = 回存-1** | 看该文件是否存在、mtime 是否随退出更新、能不能改名 |
| **存-3 存档里是「类型不对的值」**（本轮新发现的缺口） | 客户端自己只写数字 ⇒ 只有手改 / 异常写入才可能 | ★ `tick`（`OnUpdate`，`985` 起）**没有 pcall 包裹**，且 `c.speed`（1009 等 `(c.speed or 90)`）与 `s.dur = c.duration or 2.0` 在载入期**只补 nil、不做类型归一**（只有 `faEdge`/`fontTier`/`inOffY` 三个做了） ⇒ 值若是 table 就是**每帧一次 Lua 错误** | 打开那份 `.bak` 看 `speed`/`duration`/`clampPct`/`posX`/`posY` 是不是数字 |

### 8.2 「进世界那一拍崩」的账号级签名（不用改任何东西就能问出来）

EH_Damage 存档是**账号级**（toc 只有 `## SavedVariables`，**没有** PerCharacter）⇒ **同一账号所有角色共用一份**：

- **同一账号所有角色都崩、换个账号就好** ⇒ 指向该账号的 `EH_Damage.lua`（存-1 / 存-3）。
- **换账号也崩** ⇒ **不是**这个文件（可能是客户端全局存储 / 宿主 `EvalHelp.lua`（本机 150~468 KB）/ 别的插件）。

### 8.3 为什么「进世界就崩」只能走文件层诊断

崩溃就在**进世界那一拍** ⇒ 游戏内命令（`/edmg …`、宿主的 Tab⑦）**根本敲不了/点不了** ⇒ 唯一可行的一步是
**关客户端 → 改存档文件名 → 再进**（我们**不会**让用户去翻文件找东西，就这一个改名动作）。

### 8.4 同一次 A/B 就能把「存储面」与「载入期代码」分开

- 改名存档后**仍崩** ⇒ **不是存储面** ⇒ 回到 **§3.1 `iconScan`**（进世界那一拍唯一的批量原生调用）与 **§3.2 `FontDigitsExtra` 硬索引**。
- 改名后**不崩** ⇒ 把那份 `.bak` 留着：一眼就能分「**截断**（语法错）」/「**类型异常**」/「别的」。

### 8.5 若确认要改（仍然等你点头；本轮一个字节都没动）

★ **以 §6 那张「改动 × 功能影响」表为准**（本节只是指向它，不再复述——两处并存必然漂移）：
**可做且零功能变化** = ① `iconScan` 上界现读（**不加 `""` 停止**）· ② `FontDigitsExtra` 按 `getn` 逐档写 ·
