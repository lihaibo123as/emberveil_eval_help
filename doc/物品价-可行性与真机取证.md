# ItemLens 整合可行性分析（价格 / 估值 / 对比）

> **结论速览**
> 1. **可以整合，但「整包搬进来」是错的**。ItemLens 6 项功能里 **2 项与 EvalHelp 工具箱现有「商人」分组完全重复**（自动卖灰 / 自动修理），**2 个 UI 部件与现有部件顶牛**（小地图按钮 / 独立配置窗）。
> 2. 真正有增量的是 **4 项**：商人价学习 + tooltip 价格行 · Shift 与已穿对比 · 拾取总价 · 背包/银行估值（**EvalHelp 完全没有价格数据**）。
> 3. ★★★ **最重要的一条**：客户端自带的 `unrealUI` 里已有一份**同类功能的成熟实现 + 真机结论**（`modules/itemprice.lua`）。它记着 **「替换 GameTooltip 的方法在本客户端不成立」（USER_CONFIRMED_INGAME）** —— 而 ItemLens 的**主路径正是这个**。⇒ **别照抄 ItemLens 的钩子设计，要照它的功能清单，用 unrealUI 已证的做法重写。**
> 4. **阶段 C 已完成**（三轮真机取证，六个未知点全部落地 → 见**第十二之三**）：学价机制 = 商人窗内用**自建 tooltip** 逐格扫背包，金额取自全局 `arg1`，**单价 = 金额 ÷ 该格数量**；悬停识别走 **OneBag 按钮**（48/48 可读）；替换 `GameTooltip` 方法在本客户端**确认无效**。
>    ⇒ 下一步 = **阶段 A：独立模块 `tools/ItemPrice.lua`**（价库数据已挖好：`ItemPriceData.lua`，13,994 条）。
>

## 三、本客户端事实核验（决定可行性的地基）

## 三之补（★★★）unrealUI 里的同款实现：**这是最重要的对照物**

客户端自带原生 UI 插件 `unrealUI`（**539 文件 / 70 MB**，MIT；★**现已移到 `EvalHelp\tmp\unrealUI`，只作参考、不再加载**）里已有一份同类功能的**成熟实现**：

* `modules/itemprice.lua`（757 行）—— tooltip 底部的物品价值行 + 学习
* `core/pricedata.lua`（**2,381 行 / 13,994 条**）—— vanilla 基础价表 `[itemID]="sell,buy"`（铜，抽自 pfUI 的 `pfSellData`）
* 独立存档 `UnrealUIPriceDB = { version, sell = {[id]=copper}, buy = {[id]=copper} }`

**它记录了几条 `USER_CONFIRMED_INGAME` 真机结论 —— 其中两条直接判 ItemLens 的死刑：**

| # | unrealUI 的真机结论（原话位置） | 对 ItemLens 的意义 |
| --- | --- | --- |
| ★1 | `itemprice.lua:483~491`：「**replacing a method on GameTooltip does not hold on this client**. unrealUI installed a wrapper for all ten item setters and at hover time none of them was the live method, and not one had ever run — 'hooks: 0 live, 10 replaced, 0 never installed' … **the assignment itself is what does not persist**」 | 🔴 **ItemLens 的 `InstallTooltipHook`（522，替换 `GameTooltip.SetBagItem`）在本客户端同样是死的** —— 它自己的自检会把它判成 `hookOK = false`。能活的是**按 tooltip 首行名字查价**那条（`FocusName` 558） |
| ★2 | `itemprice.lua:303~307`：「`SetTooltipMoney` was the obvious native route, and its call completed without error, but **the user confirmed that it rendered no price on this client**」 | 🟡 又一个「本客户端 widget `Set*` 静默无效」实例（与项目既有判据同族）⇒ **别走 `SetTooltipMoney`** |
| ★3 | `itemprice.lua:269~287` `ResolveAmount(a1..a4)`：「**Which position the amount arrives in depends on this client handler shape** … the first positive number wins and the legacy `arg1` global is the last resort」 | 🟠 ItemLens 的 `OnMoney` 只试 `money or arg1`（**两个位置**）⇒ 位置一变就学不到价（应照它试 a1..a4 + `arg1`） |
| ★4 | `itemprice.lua:493~504`：正确姿势 = **从被悬停的按钮识别物品**（`core/itemslot.lua:811` 在背包/银行格 `OnEnter` 上做 post-hook，调 `U.ShowItemPrice(bag, slot)`），**不是从 tooltip 识别** | 🟢 **这就是整合要实现的那条路**；也解释了 ItemLens 为什么必须双写 `n<名字>` 键 |
| ★5 | `itemprice.lua:12~16` 价格来源清单：`GetMerchantItemInfo`（买价，需商人窗）· `GetBuybackItemInfo`（卖价，**但没有物品链接可做键**）· **`GetAuctionSellItemInfo()`（卖价，拍卖出售格）** | 🟢 `GetAuctionSellItemInfo` 比第四节那个押金公式**更干净**的 AH 旁路 |
| ★6 | `itemprice.lua:252~267` `ScanMerchant` = `GetMerchantNumItems` + `GetMerchantItemLink(i)` + `GetMerchantItemInfo(i)` 逐条读**商人列表** | 🟢 ItemLens 只用「扫自己背包」这一种学价方式；**商人列表本身也是价源（买价）** |
| ★7 | 它把自己的一行**塞在 tooltip 底部并显式改高度**（`:308~`），明说「This does not depend on GameTooltip's broken AddLine relayout path」 | 🟠 ItemLens 用 `AddLine` + 手工去重（`TooltipHasText` 775）；**两者会互抢 tooltip 行** |

**对本次安装的直接意义**

1. **`unrealUI` 已被移出 `AddOns`**（现位于 `EvalHelp\tmp\unrealUI`，只作参考、不再加载；此前它在 `LIHAIBOAS1` 下也没有任何 `UnrealUI*` 存档）
   ⇒ 它**不会**与 ItemLens 抢 tooltip。**但它的源码与 13,994 条基准价表仍可直接引用**（这就是「不依赖其它插件也能做」的底气：只借**数据与已证做法**，运行期零依赖）。
   ★ 若哪天把 unrealUI 装回 `AddOns` 并启用，两套价格实现就会互抢 tooltip 行（这是必须写进方案的共存约束）。
2. **资产可白拿**：`core/pricedata.lua` 的 **13,994 条** vanilla 价表能解决 ItemLens 最大的体验短板 ——「**没去过商人就没价**」。可直接**照抄成静态兜底表**（MIT，注明出处；★诚实边界：Emberveil 改过价的物品会显示 vanilla 数，必须写明「学到真价后覆盖」）。
3. **蓝图比 ItemLens 更正确**：整合时**照 unrealUI 的已证做法**（按钮识别 + `OnTooltipAddMoney` 试四参 + 静态兜底），**ItemLens 只当功能清单与配色/文案来源**。

### 4.2 冲突与风险清单（按严重度）

1. 🔴 **ItemLens 的 tooltip 主路径在本客户端是死的**（见三之补 ★1）⇒ 照抄 = 抄一个半死实现；且 `HoverCount` 的两条后备路径在本机**也不通**：
   * `FocusSlot`(543) 只认 `^ContainerFrame%d+Item%d+$`，而本机背包插件 **OneBag** 的按钮名是 `tostring(self)..bag.."Item"..slot`（`OneCore.lua:756`）⇒ **不匹配**；

9. 🟡 **`OnTooltipAddMoney` 只试两个参数位置**（`money or arg1`）⇒ 见三之补 ★3。
10. 🟡 **拾取总价依赖聊天格式串**：`LOOT_ITEM_SELF*` 缺失时退化成正则；比「点拾取那一刻读 `GetLootSlotInfo`」脆。

## 五、整合方案（三选一）

### 方案 A（推荐）：独立模块 `tools/ItemPrice.lua`（照 unrealUI 已证设计重写）+ 只搬增量

符合项目铁律「工具类功能一律独立文件，`Toolbox.lua` 只做开启/配置入口」：

* **搬**：价格库 + 价格行 + Shift 对比 + 拾取总价 + 背包/银行估值。
* **骨架照 unrealUI（已证）**：① 从**被悬停的按钮**（背包/银行格 `OnEnter` post-hook）拿 bag/slot；② `OnTooltipAddMoney` **试 a1..a4 + `arg1`**；③ 静态 vanilla 兜底价表；④ 价格库**按 id 存**。
* **不搬**：自动卖灰 / 自动修理 → 改成给**现有商人模块**补两小件：`keep` 保护名单（卖时跳过）+ `repairmax` 上限。
* **不搬**：小地图按钮（并进 EvalHelp 小地图按钮）、独立配置窗（并进工具箱模块行 + 设置弹窗）。
* **接线面（全项目只有 3 处）**：
  1. `EvalHelp.toc` 加一行 `tools\ItemPrice.lua`；
  2. `Toolbox.lua` 的 `tbModel()`（4587 商人组附近）加**一行数据** `{ t = "mod", mod = "itemPrice", key = "itemPrice", label = L("TB_ITEMPRICE"), tip = L("TB_ITEMPRICE_TIP") }`；
  3. 模块自己登记 `EVAL_TB_MOD_ROWS["itemPrice"]`（载入期登记，与 toc 顺序无关）。
* **模块纪律**（照 `tools/LootCursor.lua`）：**自带 `local function L(k)` 走 `EVAL_L`** · **只调全局桥**（`EVAL_SAY`/`EVAL_L`/`EVAL_TB_CFG`/`EVAL_DD_OPEN`/`EVAL_CHAT_ON`）· 载入期零副作用 · **有界**计时器 · 关掉零动作 · 包装按身份还原。
* 存档：进 `EVAL_HELP_CONFIG` 子树；探针读数进 `cfg.itemPriceProbe`（登记进 `Core.lua:775` 的 `LOAD_RESIDUE_KEYS`）。

### 方案 B（最省事）：保留 ItemLens 独立插件，EvalHelp 只「读」

* 用 `type(...) == "function"` 探测 4 个导出函数，在 EvalHelp 侧显示：工具箱一行只读状态（已学 N 条价 / 背包估值）；`DataSearch` 物品详情页加一行「商人收购价」。
* 优点：**零冲突、零重复**、今天就能做。缺点：**UI 两套**（两个配置入口、两个小地图按钮）、语言仍 ru/en（**没有中文**）。
* ⚠️ 装上第一件事：**关掉 ItemLens 的自动卖灰/自动修理**（它默认 `autosell = true`！），否则与工具箱重复且污染 `tbPending` 统计。
* ⚠️ 还要记得 **ItemLens 的价格行在本客户端可能只剩「按名字」一条路**（三之补 ★1），验收时要按这个预期看。
