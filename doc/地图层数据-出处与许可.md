# 地图层数据（MapOverlayData.lua）的出处与许可

> 与 `doc/物品价数据-出处与许可.md` 同性质：**记清上游、怎么复核、许可边界在哪**。

## 一、数据是什么

`MapOverlayData.lua`（生成物，全局 `EVAL_MAP_OVERLAY_DATA`）是**世界地图探索层（探索迷雾）区域表**：
每张地图下若干「区域名 → 宽 / 高 / offsetX / offsetY」（**地图像素**，原点 = `WorldMapDetailFrame` 左上、y 向下，
与客户端 `GetMapOverlayInfo` 同口径）。消费方 = `tools/SimpleMap.lua` 的 MDQ 渲染族
（工具箱 → 缩放大地图 → `[设置]` →「**打开世界迷雾**」）。

- 规模：**53 张图 / 707 个区域**（生成时自报，异常/重复 0 条）。
- 贴图路径按 Mozz 规则拼：`Interface\WorldMap\<地图文件名>\<区域名><分块号>`（每 256×256 一块），
  **贴图本身是游戏客户端资源**，本仓库不附带任何贴图。

## 二、上游与流水线（★不依赖其它插件的目录）

```
上游 LibMapOverlayData（MozzFullWorldMap 血统的区域表）
        │  一次性导出（显式 --from + --vendor）
        ▼
doc/地图层数据-源快照.txt        ← 本仓库自带的**原样副本**、只读、不在 .toc 里
        │  node gen_mapoverlay.js（默认只读快照，幂等）
        ▼
MapOverlayData.lua              ← 生成物（进 .toc，随插件分发）
```

- **生成器不内置任何第三方路径**（与 `gen_itemprices.js` 同一口径 —— 用户在物品价那次明确要求
  「**不需要和其他插件做关联性**」）：默认只认本仓库快照；换来源必须显式
  `node gen_mapoverlay.js --from <上游路径> --vendor`。
- **运行时零关联**：任何随插件分发的 `.lua` 都不读别的插件、不依赖 `!Libs`、不做跨插件调用；
  游戏侧唯一加载的是 `MapOverlayData.lua` 这张纯数据表。
- **保真判据**：从快照重跑生成器 ⇒ 产物的**数据部分逐字节一致**（2026-09-30 实测 `true`）。

## 三、出处

- 本仓库快照取自本机 TurtleWoW 发行版内的
  `Interface\AddOns\!Libs\!MyLib\libs\LibMapOverlayData.lua`（24.7KB / 74 行），
  该文件定义全局 `MapOverlayData`，形态 `MapOverlayData["<地图文件名>"] = { "区域名:宽:高:offsetX:offsetY", ... }`。
- 这份区域表的血统是 **MozzFullWorldMap**（vanilla 时代「全图探索」系列插件的数据表）。

## 四、许可与边界（如实说）

- 上游文件**本身没有声明许可**（`!Libs\!MyLib` 是一个库集合，未见 LICENSE 段落）。
  ⇒ 本仓库只把它当**数据快照**随附，便于复核与重建产物；**若上游/作者声明了许可，以对方为准**。
- 若日后要公开发布本插件，**发布前需确认这份数据表的再分发许可**；不确定就把快照与生成物一起从发布包里排除，
  改为让使用者自己用 `--from` 从自己的客户端/插件目录导出（生成器已支持）。
- **准确性边界**：这张表是**上游数据**，不是 EmberVeil 服务端实测清单。真机已知：本机存在的大陆图
  （`Kalimdor` / `Azeroth`）与城市图（`Ogrimmar`）**表里没有**；样本 `Barrens` 的客户端叠加层与表里该图的区
  一块都不吻合 ⇒ **表与客户端地图内容可能不同源**，「打开世界迷雾」的实际效果以真机开图为准
  （离线预检脚本 = `tmp/mapdata_pretest.js`，纯读表）。
