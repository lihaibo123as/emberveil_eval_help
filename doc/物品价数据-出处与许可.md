# 物品价数据 · 出处与许可（`ItemPriceData.lua`）

> 这份文件只回答一件事：**插件里那张基准收购价表是从哪来的、能不能用、边界在哪、怎么重新生成**。
> （功能的来龙去脉与真机取证在 `doc/物品价-可行性与真机取证.md`；本文件是**数据本身的档案**。）

## 一、数据是什么

`ItemPriceData.lua` 里的 `EVAL_IP_BASE`：**13,994 条** `id = "sell,buy"`（单位：铜），
id 范围 `25 ~ 24358`，`sell>0` 13,803 条、`buy>0` 13,990 条。
它是 **Vanilla 1.12 的物品数据快照**，用途只有一个：**兜底** —— 玩家没在商人处经手过的物品，也能显示一个参考价。

## 二、出处与许可

* 快照文件（本仓库自带、不在 `.toc` 里）：`doc/items-vanilla-prices.txt`（214 KB，一行一条 `id,sell,buy`）。
* 它由构建脚本 `gen_itemprices.js --vendor` 从**当时的开发机上的一份同机插件数据**导出；
  该数据本身整理自公开的 Vanilla 1.12 物品数据（**MIT** 许可来源）。
* **MIT 许可的完整说明与致谢留在本文件**；`ItemPriceData.lua` 作为**随插件分发的数据产物**只写
  「数据是 Vanilla 1.12 快照 + 指向本文件的出处说明」，不再携带第三方插件的目录路径与名字。
* 说明：这是一份**事实型数据**（物品编号 ↔ 价格的对照），不含任何第三方代码、框架、配置或 UI。
  价格数值属于公开的游戏数据。

## 三、准确性边界（必须一起读）

1. **不是 Emberveil 实测数据**：本服**新增**的物品在这张表里**没有行**（运行期按「无价」处理，**不猜**）；
   本服**改过价**的物品会先显示快照价，**直到你在商人处学到真价**——学到即**永久覆盖**（学到的价存在存档里，本表从不写回）。
2. `sell = 0` 表示**不可卖**、`buy = 0` 表示**没有商人卖**：两者运行期都按「**无价**」处理，**绝不当作免费**。
3. 运行期价格优先级恒为：**商人处学到的真价 → 本表（显示时标「基准」）→ 无（一行都不显示）**。

## 四、怎么重新生成（可复算）

```
node gen_itemprices.js              # 读 doc/items-vanilla-prices.txt → 写 ItemPriceData.lua（幂等）
node gen_itemprices.js --vendor     # 需要换来源时：把指定上游重新导出成本仓库快照
node gen_itemprices.js --from <路径> # 指定上游（Lua 表形态 id="sell,buy"）
```

* **幂等判据 = `meta.sig` 不变**：当前 `sig = 608692944`。
  换了数据来源、但**内容一致**时它必须仍是这个数（本次「去第三方痕迹」的收尾就是靠它自证的：数值一字未变）。
* 生成物**绝不手改**；数值变动一律走生成器，并同步更新本文件的条数与 sig。
* 生成器只读本仓库的快照 ⇒ **上游插件目录删掉也不影响重新生成**。

## 五、离线验证

`node tmp/itemprices_harness.js`（fengari 真跑）：

* `meta` 自报的条数/范围/sig 与真实内容一致；
* **全量 13,994 条逐条对账**（Lua 侧取值 == 快照文件）；
* 运行期那句解析（`string.match(s, "^(%d+),(%d+)$")`）真能取到 `sell/buy`；
* 边界：`sell=0` 的条目**照原样保留 0**（模块按「无价」处理）、表里没有的 id 取到 **nil 而非 0**。
