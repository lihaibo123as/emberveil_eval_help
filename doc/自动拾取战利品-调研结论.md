# 自动拾取战利品 · 调研结论（**已放弃**）

> 定案：用户 2026-09-27「**这个功能放弃**」；调研 2026-09-27 · 插件 1.75.x · 子插件 `DBX_BUILD = "1.74.34-34"`（探针已下架）。
> **一句话结论**：本客户端的「拾取」**不在 Lua 层** —— 拾取按钮的 Lua 处理体（`Interface/FrameXML/LootFrame.lua` 第 **171** 行）在把**引擎注入的全局 `this`** 给对之后能**正常执行完**，但**物品/金币不会进包**；`Button:Click()` 能触发**原生**处理体（点 `LootCloseButton` 真能把窗关掉），但对**拾取**无效。⇒ 插件**无法**自动拾取。
> ★★**别再重复这三轮**：核心判据就一条 ——「**给对 `this` 也不拾取**」。

## 2. 真机取证（三轮探针，全部在游戏内跑）

### 2.1 帧与对象事实
- `LootFrame` **256×256**，**常驻**（FrameXML 载入即建，没开窗也在）；开窗实测「子件 7 个 · region 5 个」。
- ★**本客户端 `LootFrame:GetRegions()` 也会把按钮当 region 返回** ⇒ 图层列表里显示成 `纹理:LootButton1`；**别按 `region:` 路径判定按钮**。
- 按钮：`LootButton1..4`（`_G` 里有全局名；`GetChildren()` 里找到的对象与全局**是同一个对象**），`GetObjectType()` 的字面量 = **`LootButton`**（不是 `Button`）。
- 同族还有：`LootCloseButton`、`LootButtonNIconTexture/Text/NormalTexture`、`GroupLootFrame1..4`（需求/贪婪 roll 全套按钮与纹理）。

### 2.2 事件名（实测可注册，5/5）
逐个 `RegisterEvent` + `pcall` 全部成功：
`LOOT_OPENED` · `LOOT_SLOT_CLEARED` · `LOOT_CLOSED` · `START_LOOT_ROLL` · `CANCEL_LOOT_ROLL`
（旁证：本仓 `doc/通道信息记录.md` 的真机抓包里有 `LOOT_OPENED=3` / `LOOT_SLOT_CLEARED=2` / `CHAT_MSG_LOOT=2`。）

### 2.3 三轮结果（决定性证据）

**第一轮**（`DBX_BUILD 1.74.34-30`：`/edb loot` 报告 + `loot 点`）

```
slot1 多汁狼肉 x1 品质1 图标√ link=[多汁狼肉] isItem=1 isCoin=nil · OnClick×（没挂 OnClick） LootButton1
Button:Click() slot=1 · 按钮=LootButton1 · 点前=多汁狼肉 x1 · 调用=成功
读回 slot=1：**还在** 多汁狼肉 x1 没拾取到 ｜ 窗口=还开着
```

⇒ 当时判「没挂 OnClick」，后被证明是**报告跑在开窗那一刻、处理体还没挂上**的时序假象（第二轮加「开窗后 1 秒复查」后消失）。

**第二轮**（`-31/-32`：加 1 秒复查 + `三连`）

```
LootButton1 HasScript=true Lua=有 来源=[string "return function() ..."]
slot1 9 铜币 isCoin=1 · slot2 初级治疗药水 isItem=1
Button:Click() slot=1 调用=成功 → 读回：**5 秒内仍在** ⇒ 没生效（窗口=还开着）
点 LootCloseButton：HasScript=true Lua=无（原生或没挂）· Click=成功 → 1 秒后 IsShown=false ⇒ **窗真的关了**
```

⇒ ★`Click()` **机制本身没问题**：既能跑 Lua 脚本，也能触发**原生**处理体（`LootCloseButton` 没 Lua 脚本却关掉了窗）。

**第三轮**（`-32/-33`：`三连` 四招 = 裸调 / `fn(btn)` / `this=btn` / `this=btn` 保持不动）

```
三连第 1 招【裸调 fn()】     调用=报错: [string "Interface/FrameXML/LootFrame.lua"]:171: attempt to index a nil value
三连第 2 招【fn(btn)】      调用=报错: 同上
三连第 3 招【this=btn; fn()】调用=成功（等 1.5s 看槽） → 1.5s 内没清空
★★ 四招都没生效 ⇒ 直调 OnClick / 借 this 这条路也不通
```

⇒ **两条硬事实**：
1. 处理体是**客户端 FrameXML 的 Lua**（源码文件 `Interface/FrameXML/LootFrame.lua`，出错在**第 171 行**），它读的是**引擎注入的全局 `this`**（不给 ⇒ 第 171 行 `index a nil value`；给对 ⇒ 不报错）。
2. **给对 `this`、处理体跑通，仍然不拾取** ⇒ 拾取不在这层 Lua：要么它内部调的是**受保护**函数（静默无效、不报错），要么真正的拾取在**原生层、只认真鼠标（硬件事件）**。

### 2.4 离线读客户端源码的尝试（失败）
- 客户端 UI 在 UE pak 里（`Content\Paks`，全目录约 **13 GB**，含 11~14 号 3 GB 级包）。
- 全量明文扫描 `LootFrame` / `LootFrame.lua` / `LootButton` / `LootButton_OnClick` ⇒ **0 命中**。
- 能看到的明文只有**少量 XML 包装**，例：`pakchunk0-Windows.pak` 里 `<Ui xmlns="http://unrealazeroth.ru/wow/ui/" …><Script file="CombatFeedback.lua"/></Ui>` ⇒ **Lua 是压缩存储/运行时编译的**，`LootFrame.lua` 第 171 行**离线读不到**。
- 唯一可行的内省手段（探针里已用过）：`string.dump(fn)` 抠字节码里的可读符号（Lua 5.1 的 `GETGLOBAL` 后紧跟常量名）+ `debug.getinfo(fn, "S")`（本机返回 `source=[string "Interface/FrameXML/LootFrame.lua"]`、`what=Lua`）。

## 3. 判定（为什么不做了）

1. **`LootSlot` 这条已被客户端改语义**（只剩「确认绑定装备弹窗」）⇒ 香草时代的「循环 `LootSlot(i)` 拾取」在本客户端**天然失效**。
2. 唯一入口「点击拾取按钮」在 **Lua 层跑得通但不生效**；**原生层对软件点击不开门**（对照组证明原生处理体本身是可触发的 ⇒ 挡住的正是「拾取」这个服务器写动作）。
3. ⇒ **插件自动拾取不可行**，功能**已放弃**（不再尝试 §4.3 之外的方案）。

## 4. 若将来仍要碰（可复用资产 + 复现骨架）

### 4.1 探针骨架（已下架，需要时按此重建）
- **事件探针帧**：`CreateFrame("Frame", "EH_DB_LOOT", WorldFrame or UIParent)` + 逐个 `pcall(RegisterEvent)`（「注册调用失败」与「注册成功但从不触发」要**分开**如实报）；★`OnEvent`/`OnUpdate` 回调**零形参**，事件名读全局 `event`、dt 读全局 `arg1`。
- **命令族**（挂在 `/edb`）：`loot`（报告）· `点 [槽]`（`Button:Click()`）· `直点 [槽]`（直调 Lua OnClick）· `三连 [槽]`（多上下文试验）· `字节 [槽]`（`string.dump` 抠符号）· `调 <函数名> [槽]`（按名直调含 loot 的全局；安全闸门 = `^[%w_]+$` 且名字含 `loot`）· `自测`（自建挂 Lua OnClick 的按钮再 `Click()`）· `关`（点 `LootCloseButton` 对照）· `全局`（只列**函数型**全局、上限 300、排序）· `全`/`停`/`清`。
- **判据**：轮询式（0.2s 一次、最长 5s），报「**+Nms 该槽已清空**」或「**5 秒内仍在**」；读数落 `EH_DEBUGBOX_CFG.loot`（有界环；`/reload` 后可直接读 `%LOCALAPPDATA%\Azeroth\Saved\Account\<账号>\SavedVariables\EH_DebugBox.lua`）。

### 4.2 四条别丢的经验
1. **成功判据只能按槽读回**（`GetNumLootItems` 拾取后**不缩减**，数不变 ≠ 没拾取）；★**读不到 ≠ 已空**（`GetLootSlotInfo` 抛错要单独报）。
2. **按钮两条解析路**（`_G["LootButtonN"]` 与 `GetChildren()` 里按 `GetID()` 匹配）并核对是否同一对象；**不要**用 `GetRegions()` 的路径判定（那只是显示分支）。
3. **直调 OnClick 的多招法**（裸调 / `fn(btn)` / `this=btn` / `this=btn` 保持）= 一次分清「吃 `this`」还是「吃 `self`」；写法：`local old = this; this = btn; pcall(fn); this = old`。★本轮正是靠它把报错钉到 `LootFrame.lua:171`。
4. **要有对照组**（`LootCloseButton`：有原生处理体、无 Lua 脚本）来证明 `Click()` 到底有没有效 —— 没有对照组就会把「Click 无效」误判成根因。

### 4.3 未走的替代方案（等用户定）
- 只做**提示**：`LOOT_OPENED` 后读槽，在聊天里播报「这具尸体里有 XX（品质 N），值得捡」——零风险、不代点。
- 只做**高亮标记**：在拾取窗上给命中名单的那一行加标记（透明热区/边框），**手点**——不碰服务器写动作。
