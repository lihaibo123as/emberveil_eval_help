# EvalHelp — All-Class Toolkit

> 🌍 Languages: [中文](README.md) · **English** · [Русский](README_ru.md) (in-game language: flag switcher at the top-right of the config window)

> 📢 **Release channel (KOOK)**：[emberveil 一键宏 · 插件发布](https://www.kookapp.cn/app/channels/7071527711947717/5336773639081280) — **every release is announced there** (one post for the main addon and one for each sub-addon), with a change summary, screenshots and download links.

> 🗣️ Note: rule text (skill names / condition keywords / import-export snippets) stays in the client language (Chinese) — the rule data layer is never translated.

> EmberVeil (1.12.1 / Lua 5.1) **all-class toolkit addon**: a one-line macro body `/run EVAL_GO()`, driven by a rule engine — **five skill categories** (character actions / character skills / pet commands / target selection / item use) × **71 condition types** (7 dropdown groups: self · target · auras · party·raid · party/raid pets · skill/casting · candidate — the 4 "candidate" ones appear only on the member-picker row) × multiple key-bound profiles, all configured visually, for any class. Five more built-in pages: a **Toolbox** (**UI tools** · merchant · party/social · quests · three helpers · rare-alert relay — **the full row list is in the table below**), **Quests & Gear** (chains · gear · four search kinds + a world-map annotation layer, requires UnrealQuest), an **Icon library** (the client-built-in macro icons: grouped, hover shows the path, searchable and pageable), a **Pet helper** (pet abilities → taming source → spawn-point lookup) and **Sub-addons** (enable/disable optional sub-addons).

## 🏁 Milestones (1.52.0 → 1.76.6)

- **🧾 New tool “Trade log” + 🛒 bulk buying + 🎯 two new condition types (target player / target’s target) + 🖼️ the popup-border recipe promoted to a project-wide standard** (1.76.1): the trade log docks to the **right of the trade window** every time it opens (time / partner / gold / item icons · wheel paging · left-click to whisper, right-click to delete one, [Clear] with a two-click confirm); bulk buying exists because the stock merchant UI **has no split frame at all** (the client’s `GetMerchantItemMaxStack` is always 1), so taking over Shift+right-click **loses nothing**; both conditions **default to your own name when left blank** (“target’s target” = the tank reading “my target is looking at me”), matched exactly, and **any lookup failure fails honestly — including the “no” direction**.
- **🪙 The trade-log gold column, closed over four rounds (1.76.3 → 1.76.6, accepted on a real client: “it works now”)**: from “gold always shows —” all the way down to the root — ① **the money events come one per side** (the client’s own `MoneyTypeInfo` pairing: `PLAYER_TRADE_MONEY` covers only my side, **`TRADE_MONEY_CHANGED` is the other side, and we had never registered the latter**); ② a **pure-Lua fallback read path** (no engine API involved) plus separating “**cannot read**” from “**read 0**”; ③ an empty trade slot returns a **fake link instead of `nil`** (emptiness is now judged with the client’s own ruler); ④ the panel hugs the trade window (measured **1 logical px = 2 image px**) and “list content overlapping the grey lines” is fixed; ⑤ **the most surprising one**: the minus in front of the gold I gave **was never drawn at all** — this client’s font has **no glyph for U+2212 “−”** (a silent missing character) ⇒ the column now uses **ASCII red `-` / green `+`**, and the project gained a standing **“missing glyph” gate** (the same character was also breaking the WorldFog edit panel’s “W −” / “H −” buttons at the time).
- **⚔️ Two sub-addons shipped (1.76.2 / 1.76.6)**: **EH_DPS 0.2.6** fixes “active time turns negative” (a cross-session clock stamp restored from the save file was still used as the delta base ⇒ a negative increment, and the “under one second counts as one second” denominator gate inflated it 60,000×; three gates: clock rollback, session-stamp normalisation, denominator trust); **EH_Damage 0.2.46 → 0.2.48** closes two **load-time** out-of-range paths (the spellbook scan bound is now **read live**, and the font-metric table’s per-tier hard indexing became “**ask whether it exists and whether it is a table**”) — both are the root causes behind “other players crash on the loading screen”.
- **🎒 EH_Bag 0.3.49: “Sort bags” algorithm optimisation — option A “nearest-home park” adopted (measured −12.3% steps) + three selectable algorithms (`a` / `b` / `orig`)** (1.76.0): the move order and **every safety rule are unchanged** — only “where the displaced item gets parked” got smarter: it now prefers **its own final slot** (when that slot is empty) and falls back to the old “first empty slot”. Measured over 8 fixtures: **1029 → 902 steps (−12.3%)**, and **−25%** on the big case (bags + bank: 255 → 192). **Zero regression**: identical final layout **cell by cell**, **0 swaps**, still one `PickupContainerItem` pair per beat plus a full re-read every step. New settings row **“Sort algorithm”** + `/ebag algo a / b / orig` (`b` = the more aggressive optional “fill the holes first”, measured **−38.3%**; `orig` = the original algorithm, **kept as the baseline**), and `/ebag algo` shows the per-algorithm average seconds / steps / items so you can A/B them yourself.
- **🔇 The “debug log” master gate now defaults to OFF + 📬 EH_Mail 0.3.19 → 0.3.23 (mail-log page wrap-up)** (1.75.119): ① the previous version turned off the wrong thing — this one hits the **real switch**: the gate for everything the add-on says in chat by itself now **defaults to off** (judged only by the “you touched it yourself” stamp, so an upgrade **never overrides your choice**; **echoes of commands you type still show**, and `/eh logdump` still records). It also fixes `/eh logclear` wiping the gate’s real value together with that stamp. ② EH_Mail: **take-actions are now conditional on the client’s own rules** (only for mail that really has money / attachments) and out-of-range guards moved ahead ⇒ no more spam of “internal mail database error” (new read-only probe `/tm 错误`); the third tab is **always visible** and renamed **“Mail Log”**; **mail logging is back to “recording by default”** (the “default off” line in 1.75.117 is obsolete); a new **Clear** button in the page header (**two-click confirm**) + **right-click an icon to delete one record** (matched by record identity, so an active filter can never make it delete the wrong one).
- **🗑️ New tool “Auto-discard helper”** (1.75.118): a draggable “discard” icon — **right-click it to pick items straight from your bags**, the strip to its right toggles on **left-click** and removes on **right-click**, Ctrl+wheel resizes the icon; discarding now runs **an active bag check once per second** (no longer waiting for bag events, so junk already sitting in your bags gets cleared too) and every real discard prints a **red, hard-wired line with a clickable item link** (not affected by the debug-log switch).
- **🆕 New sub-addon EH_Mail (mailbox enhancement + API checkup), shipped for the first time** (1.75.117 / EH_Mail 0.3.0 → 0.3.18): half of it is a **read-only checkup probe** (`/email`, 114 client names — the first on-client run found **nothing missing**, with one real problem, the **R11 region-index overflow**, already fixed in the port; results go to its own bounded ring and it **auto-`/reload`s 6 seconds later** to persist); the other half is the **ported mailbox enhancement**: multi-attachment sending · batch take / return / delete · an **icon-grid log page** (one cell per mail, hover for sender / subject / attachments / money / COD / time, **click to jump to the compose page with that party filled in**) · account-wide recipient history with autocomplete · an **attachment pick-list that is pure data** (you pick in your bags and the attachment slots are only a projection ⇒ **nothing is ever picked up while you choose**; the items are only moved for real at the moment you press Send) · **closing the mailbox voids the selection** (the "attachment" overlay on your bag slots and the client's own greying are cleared on the spot). The chat prefix is now **`[EH_Mail]`**; the mail log is **off by default**, and only **your own** `/tm log` counts ⇒ an upgrade never overrides your choice.
- **🎯 New tool "target health display" + the add-on ships its own creature health database** (1.75.113 → 1.75.116): this client gives **only a percentage** for hostile targets, so the add-on looks a creature up by **name + level** and recomputes the real numbers (sampled **47/47 identical** to the official database `health.max`, **0 conflicts** for (name, level)); when it cannot tell, it reports **just the percentage** rather than inventing a number; the presentation was re-judged twice from on-client screenshots and finally draws **a single line of white numbers centred on the client's own target health bar** (font and colour copied from the player frame), with a `[settings]` multi-select for value / percentage, **on by default**.
- **⏱️ The swing / auto-shot timer bar is smoother: the thin bar refreshes per-frame on demand, and ranged timing no longer depends on Chinese/English combat text** (1.75.112): the timer used to move at best once every 0.15 s; now it refreshes every frame **only where it is actually needed** — the rule is window visible ∧ combat section on ∧ truly counting down (`rem > 0.05`), and the moment that stops being true the frame **detaches itself in the same frame** (never resident, no `/reload`); ranged auto-shot timing gains a **language-independent event channel** (`ACTIONBAR_UPDATE_COOLDOWN`) that **self-validates first** (event cadence ÷ attack speed must land in 0.75–1.25 with at least 4 in-band samples), and anything that fails validation **is not adopted at all** — the text anchor keeps working; three live A/B rounds confirmed the adopted channel matches the events line by line.
- **🗡️ EH_Damage combat numbers overhauled (0.2.37 → 0.2.43)**: glyph assets grew to **three sets / nine styles** (5 parametric outlines on the built-in font · 9c original · ancient wuxia), and the panel now has separate **Font set** and **Outline style** steppers; parameters are grouped into **Motion · Position · Glyph · Scale animation**, the checkbox grid became **3 columns**, and the panel background is now **fully opaque** (no more floating numbers bleeding through); **crit amplitude cap 100% → 200%**; the "yellow blocks" in the panel are fixed (the group header's 1 px divider never received a size because `pcall` was missing `self` ⇒ the client drew it at its ≈32×32 default as a gold block); plus two real screenshots and docs (no runtime code changed).

## 🧩 Case Templates (12 groups, 40 ready-made profiles)

> No need to build from scratch. Config window → "One-key macro" tab → **`[Case Templates]`** at the bottom → pick one by class, **click to import**.

| Item | Description |
| :-- | :-- |
| **Entry** | Config window, "One-key macro" tab, bottom `[Case Templates]` button |
| **Contents** | **12 groups / 40 profiles**: 战士 / 骑士 / 猎人 / 盗贼 / 牧师 / 萨满 / 法师 / 术士 / 德鲁伊 / 通用法系 / 通用 / 队伍·团队 (group headers keep the addon's own names) |
| **Layout** | Two columns by group, wrapping inside a group; **hover** a row to see its skills and conditions |
| **Import** | One click turns it into a profile — then edit, rename and bind a key as usual |

The **Party·Raid** group (6 profiles) covers one-key healing and one-key dispelling. All of them are written as
"**explicit skill + party (raid) member condition**": the condition scans the group, picks the lowest-HP member,
switches target, casts, and restores your original target — **you never click a teammate**.

> 💬 Got a good profile? Share it in the addon comments, or use `[Share]` in the config window to post it to guild / party / say.

## Quick Start

1. Drag the skills you want onto your action bars (any class — the plugin recognizes whatever is on your bars).
2. In game, run `/eh go rescan` so the plugin learns the slots (`/eh go` shows the scan result).
3. **Bind a key (recommended, click-only)**: right-click any profile (the profile row in the combat UI or the profile list in settings) → Profile Manager → pick a key in the Hotkey dropdown → [Save] — pressing it runs that profile. **Alternative** if you prefer macros: create a macro with the one-line body `/run EVAL_GO()` and drag it onto a key. ★**Hotkeys are per character**: every character on the account keeps its own bindings (reconciled automatically on login, so another character's keys never follow you here).
4. **New here?** Type `/eh guide` for the four-step starter guide (combat UI → first profile → key binding → skill log); it also plays once automatically on first login.
5. Start from a **case template**: open `/eh cfg` → one-key macro tab → [Import/Export] → [Case Templates], pick your class and import — then tweak thresholds via the golden EH icon by the minimap; `/eh debug` shows the decision reason for every key press in chat.

## Self-Rescue (read this first when something's wrong)

1. **`/reload` first**: skills not recognized, UI glitches, just updated addon files — a reload fixes the vast majority of cases (your config is saved and won't be lost);
2. Moved skills around / dragged new ones onto bars → `/eh go rescan` to rescan;
3. Want to watch the decision process → `/eh debug` (why each skill fired or didn't, per-condition √/×);
4. Still stuck → file an Issue at <https://gitee.com/xeval/emberveil_eval_help.git> (attaching an `/eh st` status screenshot + the log file helps a lot).
5. **A shared profile never fires some skills**: usually that aura's texture was never learned on this machine — it is now scanned by name and learned automatically; `/eh go tex` lists the table, `/eh go texdel <name>` forgets one, `/eh go texclear` wipes it;
